- Полный локальный прогон на Windows 11 и Python 3.14.3: **245 passed, 1 skipped**. Пропущено создание символической ссылки без необходимого разрешения Windows; проверки жёстких ссылок прошли.
- Пять реальных принудительных завершений отдельного процесса: обход, передача файла, публикация подтверждённого результата, отчёты и ZIP. После перезапуска задача продолжена, данные проверены.
- Поддержка 20 потоков, ограничения параметров, постоянные имена отчётов и журнала, сохранность вручную изменённых файлов, согласованный снимок отчётов при длительной упаковке.
- История с поиском, страницами, архивом и защитой удаления; сохраняемая последовательная очередь и ожидание ручного подключения.
- Резервные копии SQLite с WAL, ограничение числа автоматических копий, экспорт/импорт, отказ при повреждённом файле, восстановление без удаления результатов.
- Локальная проверка обнаруживает пропуски и повреждение содержимого без токена; очистка сохраняет части из локального состояния и переносимой описи.
- Проверены CSRF/Origin для новых API, адреса обновлений, небезопасные пути ZIP и обязательная проверка digest SHA-256.
- Проверен собранный Windows EXE: трей, соответствие статических файлов исходникам, офлайн-проверка двух результатов, резервная копия, реальная корзина Windows и создание ZIP без токена.
- На изолированных копиях EXE проверены установка обновления и откат при несовпадении ожидаемой версии. История сохранена в обоих сценариях. Для проверки механизма использована одна и та же сборка с разными ожидаемыми подтверждениями версии.
- В браузере проверены собственный выбор режима, расположение меню в пределах окна, инструменты, локальная проверка, резервная копия и закрытие уведомления об ошибке внутри диалога. Ошибок JavaScript не обнаружено.

GitHub Actions подготовлен для Windows/Linux и Python 3.11/3.14. Облачный запуск workflow не выполнялся: он начнётся после добавления файлов в репозиторий. Проверка в реальном облачном аккаунте на протяжении нескольких суток, физическое отключение питания и намеренный синий экран не выполнялись. Аварийное завершение воспроизводилось только в изолированных тестовых процессах.

Проверен переход между версиями с сохранением прежней истории и автоматической резервной копией перед обновлением базы.
