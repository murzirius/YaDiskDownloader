# Проверка восстановления накопителя и статистики — 1.5.0

Сборка **20261022.2**, Windows, 22 октября 2026 года.

## Исправления

| Проблема | Изменение |
| --- | --- |
| Непонятная причина недоступности папки | Отдельные сообщения о пропавшей папке, правах доступа, обрыве связи с NAS и долгом ответе; код ОС без сырых путей и текста исключения. |
| Продолжение требовало ручного вмешательства после каждого обрыва | Для ранее подтверждённой папки — проверки через 2, 4, 8, 16, 32 и 60 секунд. Ручная пауза и остановка отменяют автоматическое продолжение. |
| Повтор одного файла в нескольких потоках после восстановления | Повторная попытка сохраняет статус `running` и принадлежность прежнему потоку. |
| Статистика ждала ответ накопителя | Оперативные счётчики используют подтверждённые размеры и текущие данные записи. Полный подсчёт файлов работает в фоне и публикует промежуточный результат. |
| Неясно, сколько скачано сейчас и сколько было раньше | Панели «Всего» и «Эта сессия», отдельный живой прогресс проверки. |
| Ошибка проверки превью могла убрать сведения о пригодном оригинале | Ошибка превью не отменяет уже проверенный оригинал. |
| Запись журнала и описи на отключённый NAS при завершении | Новые экспорты откладываются при известной недоступности папки; история остаётся в базе приложения. |
| Подмена корневой папки ссылкой или junction | Запись заблокирована; другой накопитель или папка не принимаются автоматически. |
| Время сессии включало последнюю паузу после остановки | Пауза исключается и при завершении задания из состояния паузы. |

## Границы проверки

Отключение накопителя моделировалось ошибками файловой системы на искусственных файлах. Физическое отключение USB и реального SMB-сервера, длительная загрузка из реального аккаунта Яндекса и повторная сборка этого дополнения на Linux/macOS не проверялись. Нативные кнопки мини-окна и трея в этой сборке отдельно не нажимались.

Если операционная система уже зависла внутри чтения или записи на NAS, Python не может гарантированно прервать такой системный вызов. Новые проверки ограничены числом фоновых потоков, интерфейс получает состояние независимо, а запись в новую папку вместо пропавшего накопителя не запускается.
