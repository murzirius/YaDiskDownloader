# Проверки и измерения 1.3.8

Измерено 18 октября 2026 на одном Windows-ПК, Python 3.14.8, SQLite 3.51.3. Сравнение с кодом 1.3.4. Метрики собраны на кандидате 1.3.5; в окончательной 1.3.8 отдельно исправлено отображение объёма после ручного удаления файла и добавлена итоговая фоновая сверка объёма после загрузки/ZIP. Код самой проверки файлов при этом не менялся. Числа ниже не выдаются за повторный замер после этого исправления. Все данные искусственные, без токена и доступа к пользовательскому Диску.

## Проверка готовой папки

Каждый файл содержит 4 байта. Есть опись, доверенный локальный кэш и неизменившиеся подписи Windows. Таймер включает проверку и получение итоговых счётчиков. Оба варианта используют одинаковый измерительный инструмент с tracemalloc и подсчётом SQL. Это проверка накладных расходов, а не скорости чтения больших видео.

| Файлов | Время до / после, с | CPU до / после, с | Соединения до / после | COMMIT до / после | Пик выделений Python до / после, КиБ |
|---|---|---|---|---|---|
| 100 | 1.183 / 0.221 | 0.984 / 0.219 | 305 / 3 | 100 / 0 | 114 / 234 |
| 1000 | 12.819 / 1.946 | 10.406 / 1.938 | 3009 / 3 | 1000 / 0 | 329 / 650 |

Небольшой дополнительный буфер для порции записей ограничен размером порции. Артефакты, сохранение частей, публикация файлов и SQLite synchronous=FULL сохраняют прежние гарантии. Объединены только восстановимые отметки проверки; неизменившиеся отметки не переписываются.

Отдельный большой прогон после оптимизации (таймер только проверки, без итогового summary):

| Файлов | Время, с | CPU, с | Пик выделений Python, КиБ |
|---|---|---|---|
| 10000 | 31.00 | 30.00 | 691 |
| 100000 | 255.19 | 243.08 | 552 |

Пик выделений tracemalloc относится к измеряемой операции, **не ко всей памяти процесса**. Повторного хеширования неизменившегося содержимого в этом сценарии нет. Изменённые файлы, недоверенная внешняя опись и неподдерживаемые подписи требуют чтения содержимого. Офлайн-проверка проверяет содержимое независимо от кэша.

## Исправления и регрессии

- Временная ошибка метаданных не удаляет запись о сохранённом файле.
- Офлайн-проверка включает ещё не скачанные файлы; постраничный список не ограничивает выбор дозагрузки.
- Неполная/отменённая проверка не используется как полный список для ремонта.
- Сбой сохранения описи виден пользователю; её можно обновить без ключа.
- Очередь учитывает ручной запуск своего задания; заблокированное задание можно повторить отдельной кнопкой.
- Исправлены поиск русских названий и устаревшие ошибки обхода в объединённом отчёте.
- Недоступная папка не отображается как пустая.
- При переходе между заданиями очищается выбор ошибок; фокус клавиатуры сохраняется при обновлении списка.
- Старые счётчики не выдаются за итоговую статистику нового этапа.
- Подготовка прежней истории и восстановление публикаций выполняются в фоне с защитой от конфликтующих действий.
- Долгие операции проверки частей и записи журнала проверяют отмену. События остаются в SQLite, даже если обновление большого HTML отложено.

## Что проверено реально

- Полный локальный прогон: **367 passed, 1 skipped**. Пропуск — создание символьной ссылки без нужных прав Windows.
- Дополнительные регрессии и проверки новых HTTP-действий, CSRF и восстановления.
- Ручная проверка веб-интерфейса: главный экран, три шага, проверка папки назначения, выбор ошибок клавиатурой, офлайн-проверка и дозагрузка. В тестовой дозагрузке 23 готовых файла учтены, скачан один отсутствующий; итог — 24 оригинала.
- Настоящий EXE 1.3.8 запущен на Windows: интерфейс, история, ожидание очереди, выбор папки, выход через HTTP и нативный значок в трее. В обоих случаях дочерние процессы завершились и порт освободился. SQLite 3.51.3, WAL.
- CMD-архив распакован в новую папку. Запущен именно start.cmd: созданы окружение и зависимости, открылись HTTP и выбор папок, выполнена проверка назначения и штатный выход. Python 3.14, SQLite 3.50.4 использует безопасный режим DELETE.
- ZIP-пакеты проверены по CRC. В публичную поставку входят только Windows EXE и Windows CMD.

## Ограничения проверки

В этой серии проверок не использовался реальный аккаунт Яндекса. Ограничения API и доступность конкретных облачных файлов не подтверждались. Проверялось принудительное завершение процесса, но не настоящий BSOD, отключение питания или неисправный накопитель. Ночной прогон, разные HDD/SSD и сетевые папки требуют отдельного испытания.

## Воспроизведение

`python tools/benchmark_verification.py --source . --output verification.json --sizes 100 1000 10000`

`python tools/benchmark_performance.py --source . --output benchmark-download --case download --files 300`

Для второго варианта используйте отдельный каталог с кодом 1.3.4 и тот же Python/SQLite. Каталоги результатов должны быть новыми. Измерения работают только с создаваемыми тестовыми данными.

Изменения разделены на коммиты основной ветки; откатывать зависимые изменения следует в обратном порядке. Переустановка старой программы сама по себе не удаляет пользовательские файлы.

Дополнительно проверена отмена записи описи после SQLite commit и ожидание фонового сохранения перед финальной записью. Основные измерения выше выполнены на кандидате 1.3.5; алгоритм проверки файлов в итоговой сборке сохранён.
