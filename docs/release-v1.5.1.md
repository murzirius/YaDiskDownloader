# YaDiskDownloader 1.5.1

Перед восстановлением истории прочитайте предупреждение в окне приложения.

## Запуск и история заданий

- Большая история получает больше времени на резервное копирование при обновлении. Окно запуска показывает этап; при ошибке можно открыть небольшой файл диагностики.
- Если история не проходит проверку SQLite, Windows-приложение сначала готовит отдельную копию. Повреждённые индексы перестраиваются только на копии, затем выполняется полная проверка. Применение требует подтверждения.
- Если восстановить индексы не удалось, приложение ищет проверенную резервную копию и показывает её имя и дату. Более новые задания, прогресс и настройки могут отсутствовать после восстановления старой копии. Скачанные файлы не удаляются.
- Перед применением сохраняется отдельный снимок исходной истории. Отказ от восстановления оставляет текущую базу без изменений. Проверка целостности остаётся обязательной.
- После подтверждения окно показывает сохранение исходной истории, применение копии и проверку результата. При копировании видны объём и процент текущего этапа; при проверке и подготовке заданий — прошедшее время. Применение получает отдельный лимит обработки: подготовка копии и время чтения подтверждения не расходуют его.
- Во время восстановления показана заметная плашка: операция может занять несколько минут. Она исчезает после запуска приложения.

Подробнее: [восстановление истории](https://github.com/murzirius/YaDiskDownloader/blob/main/docs/history-recovery-v1.5.1.md).

## Накопители и сетевые папки

- Исправлен цикл частых пауз при медленном ответе NAS. Сетевой путь получает больше времени на ответ; повторные проверки не запускают новые потоки поверх зависшего системного запроса.
- При временной недоступности накопителя программа повторяет подключение без ограничения числа попыток: через 2, 4, 8, 16, 32 и затем каждые 60 секунд. Сама проверка может занять дополнительное время.
- Автоматическое продолжение требует двух успешных проверок прежней папки. Кратковременное восстановление больше не сбрасывает задержку повторов; ручная пауза и остановка имеют приоритет.
- Кнопки управления отвечают, пока операционная система ждёт накопитель. Приложение различает проверку папки и проверку свободного места, показывает текущую попытку и сохраняет техническую причину в диагностике.
- Сохранены проверка целостности, продолжение частей файлов, защита от подмены папки и обязательная пауза при остатке меньше 500 МБ.

## Трафик и производительность

- Уменьшен объём служебных ответов и обновлений состояния интерфейса. Ограниченный кэш и повторное использование соединений сокращают повторные запросы; неиспользуемые соединения освобождаются.
- Добавлены настройки экономии трафика, лимит трафика, управляемое число потоков проверки файлов и завершение текущих передач перед паузой.
- Добавлены поиск настроек, повтор группы неудачных файлов и установка Windows-приложения в папку текущего пользователя.
- Подготовлены отдельные автоматические проверки производительности и тестового Яндекс.Диска. Для облачных проверок нужен специально выделенный тестовый аккаунт.

## Ограничения проверки

Проверки недоступного и медленного NAS воспроизводятся на искусственных данных. Скорость и стабильность конкретного сетевого накопителя зависят от Windows, локальной сети и самого NAS. Подробности: [проверка восстановления накопителя](https://github.com/murzirius/YaDiskDownloader/blob/main/docs/validation-storage-v1.5.1.md).

Финальный локальный полный прогон: 918 тестов прошли, 6 пропущены. Отдельно проверены запуск и восстановление: 35 тестов прошли. Эти наборы пересекаются; их результаты не суммируются.

Готовый Windows EXE запускался с повреждёнными тестовыми базами: проверены подтверждение восстановления, отказ без изменения базы, сохранность текущих записей при восстановлении индексов и сохранение исходного снимка при выборе старой копии. Реальная база конкретного устройства и загрузка из настоящего аккаунта Яндекса не использовались в этих проверках.
