# Восстановление истории при запуске 1.5.1

Ошибка проверки истории относится к базе заданий. Сама по себе она не означает повреждение скачанных фото и видео. Увеличение времени ожидания не устраняет нарушения целостности; приложение не отключает эту проверку ради запуска.

## Что делать

Запустите Windows EXE. Сначала программа подготовит отдельную копию и проверит её. На большой истории это может занять несколько минут.

- Если окно сообщает об успешном восстановлении индексов на копии, можно подтвердить применение. Это сохраняет текущие записи истории.
- Если индексы восстановить не удалось, программа проверит прежние резервные копии. Перед восстановлением покажет имя и дату выбранной копии. Более новые задания, прогресс и настройки могут отсутствовать; это действие требует отдельного подтверждения.
- «Нет» оставляет текущую историю без изменений. Диагностика показывает вид нарушения, не раскрывая содержимое записей.

Скачанные файлы не удаляются. После восстановления старой истории можно проверить прежнюю папку и дозагрузить недостающее.

Перед применением создаётся согласованный снимок текущей истории в `backups/recovery-originals`. Он специально помечен как непроверенный и не включается в обычный список исправных резервных копий. Не удаляйте его: он сохраняет более новые сведения для возможного последующего восстановления. Файлы WAL/SHM вручную не удаляются.

## Защита данных

Полная проверка SQLite обязательна для подготовленной копии и для восстановленной базы. Индексы перестраиваются на отдельной копии; до подтверждения оригинал не изменяется. Перед применением проверяется отсутствие внешних изменений. Эксклюзивная блокировка SQLite не позволяет другой программе записать данные во время сохранения исходного снимка и применения результата.

Применение выполняется через [SQLite Backup API](https://www.sqlite.org/backup.html), без ручной замены базы и удаления её журналов. Перед записью включается режим `synchronous=FULL`. Для операции нужен запас свободного места на диске истории. Если не удаётся сохранить исходный снимок, получить блокировку или проверить результат, операция не объявляется успешной.

## Проверки

Полный локальный набор на Windows: 908 тестов прошли, 6 пропущены. После дополнительных проверок WAL и усиления надёжности записи повторно запущен набор проверок запуска и восстановления: 109 тестов прошли, 1 пропущен. Проверено сохранение последних подтверждённых записей WAL после резкого завершения дочернего процесса и отмена применения в режимах WAL и DELETE.

На синтетической базе воспроизведены реальные отсутствующие записи индекса. Проверены согласие и отказ, конкурирующий писатель, ошибка записи, отмена во время применения SQLite Backup API, сохранение исходной копии и восстановление выбранной старой копии. Обычная проверка целостности остаётся строгой.

Настоящий Windows EXE запущен с повреждёнными тестовыми индексами. Проверены реальные окна подтверждения, успешный запуск после восстановления, сохранность всех текущих записей при восстановлении индексов, неизменность базы до согласия и при отказе, сохранность более новых записей в исходном снимке при выборе старой копии, сохранность тестового скачанного файла. Проверены также обычный запуск, ошибка неподходящего файла SQLite, диагностика и полный выход через браузер, трей и мини-окно. На готовом EXE повторены восстановление истории приложения и переносимой истории папки: по 1000 синтетических файлов в каждом случае, SHA-256 совпадает, история сохранена.

В GitHub Actions добавлены проверки этих сценариев готового EXE. Новые шаги ещё не запускались в GitHub Actions; здесь проверена локальная Windows-сборка. Реальная база конкретного устройства не использовалась в тестах; на ней программа сначала должна проверить копию и предложить доступный вариант восстановления.
