# Обход, проверка папки и продолжение загрузки

Обход запрашивает до 1000 объектов на страницу и использует не больше четырёх запросов одновременно. Теперь эти слоты используются и для страниц одной большой папки. Страницы могут прийти в любом порядке, но сохраняются строго по порядку: данные и курсор страницы записываются одной транзакцией SQLite с прежним уровнем надёжности.

При остановке сохраняется только подтверждённый курсор. Неподтверждённую заранее запрошенную страницу после перезапуска нужно запросить снова; уже сохранённые страницы повторять не требуется. Если ответ сервера стал короче ожидаемого, спекулятивные страницы отбрасываются и обход следует фактическому смещению. Повторяющиеся и недопустимые страницы по-прежнему дают понятную ошибку.

Незавершённую дозагрузку в ту же папку с теми же исходными путями, типами, исключениями и датами приложение продолжает в прежнем задании. Изменение фильтров создаёт новый обход, чтобы не пропустить ранее исключённые файлы. Продолжение незавершённого задания сохраняет прежний план и не делает отдельный запрос Яндексу для каждого уже проверенного результата. Запрос новых и изменённых файлов остаётся отдельным действием. Для ещё не скачанных файлов метаданные по-прежнему проверяются перед загрузкой.

Проверка готовых копий на медленном накопителе использует до четырёх чтений сведений о файлах. На быстром локальном накопителе сохраняется последовательная обработка. Проверка путей, SHA-256, размера и подписей изменений не удалена. Изменённые и непроверенные файлы возвращаются в обычную последовательную проверку содержимого; полная проверка и защита от дубликатов не распараллеливаются этим механизмом.

## Измерения

Сравнение с ревизией `c3fc659`, Windows, Python 3.14.8, SQLite 3.51.3. Данные создавались во временных каталогах. Это изолированные сценарии, а не измерения реального аккаунта Яндекса или NAS. Один сравнительный прогон не определяет скорость у всех пользователей.

| Сценарий | До | После |
|---|---:|---:|
| 55 000 файлов в одной папке, искусственные 100 мс на запрос | 7,86 с | 3,84 с |
| Запросы страниц в этом сценарии | 55 | 55 |
| Одновременные запросы | 1 | ≤ 4 |
| CPU в этом сценарии | 2,39 с | 2,28 с |
| 1000 готовых файлов, искусственные 2 мс на файловый stat | 8,64 с | 2,69 с |
| CPU проверки готовых файлов | 1,80 с | 2,20 с |
| Пиковая память Python при проверке | 673 КиБ | 698 КиБ |

Дополнительная работа потоков в сценарии медленного накопителя расходует около 0,4 с CPU и 25 КиБ памяти, сокращая ожидание примерно на 6 с. Число соединений с SQLite в проверке осталось 4, SELECT — 19. Быстрые локальные чтения не включают этот пул.

В инструментированном обходе 10 000 файлов добавленный индекс очереди папок сократил зарегистрированные чтения процесса примерно со 157 до 76 МиБ; записи выросли с 61 до 64 МиБ из-за обслуживания индекса. Пик рабочего набора остался около 79,5 МиБ. Это счётчики ввода-вывода процесса, включая кэш ОС, а не объём физических чтений накопителя.

Воспроизведение без настоящего аккаунта:

```sh
python tools/benchmark_scan_pages.py --baseline-ref c3fc659 --files 55000 --latency-ms 100
python tools/benchmark_verification.py --source . --output before.json --sizes 1000 --stat-delay-ms 2 --baseline-ref c3fc659
python tools/benchmark_verification.py --source . --output after.json --sizes 1000 --stat-delay-ms 2
```

## Защита места

Порог 500 МиБ нельзя отключить параметром обычной автопаузы. При его достижении новые загрузки не начинаются. Если оставшийся объём всех текущих передач известен, не больше 64 МиБ и помещается с резервом 32 МиБ, они завершаются перед паузой. В остальных случаях сохраняются части и включается пауза. Продолжение допускается после освобождения как минимум 1 ГиБ и выполнения пользовательского процентного ограничения. Во время паузы попытки и их время не расходуются.

Между проверками ОС учитываются записываемые байты, чтобы быстрая запись не расходовала весь запас за интервал проверки. Другие приложения могут одновременно заполнять накопитель; файловая система и обработка ENOSPC остаются последней защитой. Неизвестный размер не считается безопасным маленьким файлом.

## Границы проверки

Регрессии проверяют порядок страниц при параллельных ответах, короткую страницу сервера, продолжение после открытия нового экземпляра Store, повторное использование незавершённого задания, автоматическую цепочку этапов, отложенный запуск, неотключаемый порог, завершение маленького текущего файла, отсутствие запуска следующего файла и проверку изменённого содержимого после параллельного чтения подписей.

Скорость настоящего Яндекс.Диска зависит от ответа API и ограничений аккаунта. Реальный длительный обход 55 000 файлов в облаке и нестабильный сетевой накопитель в этих измерениях не использовались. Резкое изменение содержимого облачной папки во время постраничного обхода может потребовать нового обхода: API не даёт этому приложению неизменяемый снимок всей папки.
