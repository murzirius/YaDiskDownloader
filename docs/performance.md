# Проверка производительности

Нагрузочный стенд запускает приложение с искусственным Диском, отдельной историей и отдельной папкой результатов. Он не подключается к Яндексу и не использует пользовательский ключ. Нужны Windows и зависимости из `requirements-dev.txt`.

```powershell
python tools/benchmark_performance.py --source . --output C:\YaDiskBench\idle --case idle --files 1 --seconds 30
python tools/benchmark_performance.py --source . --output C:\YaDiskBench\scan --case scan --files 10000
python tools/benchmark_performance.py --source . --output C:\YaDiskBench\download --case download --files 600
```

Каждый запуск требует новую папку `--output`. Результаты сохраняются в `result.json`; искусственные файлы остаются для проверки. Для повторения используйте другую папку. Проверка может записать значительный объём данных.

Сценарии: `idle` — простой; `history` — открытая большая история; `summary` — восемь пересчётов счётчиков; `scan` — обход; `download` — загрузка; `pause` — пауза; `offline` — имитация потери связи и восстановления; `missing` — проверка и дозагрузка уже скачанной папки; `zip` — формирование архива.

Стенд измеряет время, процессорное время, среднюю и пиковую рабочую память процесса, логический ввод-вывод Windows, обращения к SQLite и задержки настоящих локальных HTTP-запросов. Процент CPU указан относительно одного ядра и может превышать 100%. Память включает сам стенд и искусственные метаданные; сравнивать её нужно на одинаковом числе файлов. Логический ввод-вывод процесса не равен физическому вводу-выводу накопителя.

Если среда запрещает TCP на localhost, параметр `--test-client` вызывает те же маршруты через тестовый клиент Flask. Поле `http_transport` явно отмечает такой режим: его задержки не включают Waitress и TCP. Сравнивать два режима между собой нельзя. Проверки готового EXE этот режим не заменяет.

Загрузка, дозагрузка и ZIP проверяют SHA-256 результатов. Дополнительно проверяется целостность SQLite, а для ZIP — содержимое и проверка архива. Сценарий `missing` проверяет полностью скачанную папку: он измеряет расходы на учёт прежних файлов, а не скорость получения новых.

Параметр `--profile` добавляет время отдельных SQL-операций в `sql-profile.json`. Это сумма интервалов исполнения по потокам, включая ожидание блокировок; она может превышать общее время запуска. Профилированные запуски нельзя использовать для сравнения скорости.

Для сравнения двух версий используйте одинаковые Python, SQLite, настройки, число и размер файлов. Выполняйте сценарии последовательно, без параллельных тестов и сборки. Повторяйте измерения и отдельно отмечайте разброс. Сетевой имитатор не измеряет реальную скорость Яндекс.Диска.

Проверка исходников не заменяет проверку EXE. Готовая Windows-сборка проверяется отдельно через `tools/smoke_windows_exe.py`: запуск без Python в PATH, встроенные ресурсы, локальные папки, восстановление истории, очередь, трей и полное завершение процесса.

Оптимизации не меняют SHA-256/MD5, проверку размеров и продолжения файлов, публикацию результатов, периодичность контрольных точек, `synchronous=FULL` и границы фиксации прогресса. Соединение SQLite переиспользуется только внутри обработки одного файла и закрывается при её завершении. Неисправное соединение исключается из повторного использования.
