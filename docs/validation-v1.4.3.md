# Проверки YaDiskDownloader 1.4.3

## Найденные проблемы и исправления

| Проблема | Исправление | Проверка |
| --- | --- | --- |
| Подготовка выполняла повторные обращения к файловой системе для имён, скачанных копий и сохранённых проверок. На NAS каждое такое обращение могло требовать нескольких запросов SMB. | Служебные сведения обрабатываются как данные SQLite, без проверки каждого пути. Проверка файлов остаётся отдельным этапом. | Сравнительный замер на 55 000 файлов и запрет обращений к путям при подготовке в регрессионных тестах. |
| Счётчик складывал разные записи одного файла и показывал сотни тысяч записей вместо числа файлов. | Список готовится с одной единицей прогресса на исходный файл, даже при наличии обеих копий. | Собственная база, переносимая опись, остановка и продолжение; настоящий EXE на 1 000 файлов. |
| Для каждого проверенного оригинала запускалась процедура удаления превью, даже если превью отсутствовало. | Процедура вызывается только при наличии записи превью в уже загруженном пакете сведений. | На 30 оригиналах проверка выполняет менее 15 SELECT; сохранность копий проверена. |
| Поиск прежней загрузки разрешал пути всех старых папок, включая недоступные сетевые накопители. | Разрешается выбранная папка; старые сохранённые пути сравниваются без обращения к этим накопителям. | Старый недоступный путь не разрешается в регрессионном тесте. |
| Возобновление переносимой загрузки могло заново выбрать источник описи вместо сохранённого при создании задания. | Читается конкретная опись, записанная в настройках задания. | Возобновление прерванного задания без повторного выбора источника. |
| Прогресс проверки мог отображаться в байтах; подсказка о занятом месте обещала учитывать журналы и ZIP. | Исправлены единицы прогресса браузера и EXE, подсказка соответствует подсчёту скачанных оригиналов и превью. | Исполнение функции счётчиков в Node.js, проверка статики настоящего EXE. |

Имена служебных отчётов остаются зарезервированными в SQLite: это не позволяет принять отчёт за скачанный оригинал при совпадении имени и содержимого. Для такой резервации файлы журналов и отчётов не открываются. Снимок прежнего списка сохраняется для отчёта об изменениях; его строки не считаются отдельными файлами для проверки.

## Измерения

Одинаковая искусственная база: 55 000 файлов и 20 000 зарезервированных служебных имён, всего 240 000 прежних записей разных таблиц. Локальная Windows, Python 3.14.8, SQLite 3.51.3. Сравниваются подготовка из 1.4.2 (`7270b18`) и 1.4.3. Подготовка данных не входит в время. Один сравнительный прогон, без имитации задержки NAS.

| Показатель | 1.4.2 | 1.4.3 |
| --- | ---: | ---: |
| Подготовка сведений | 315,136 с | 15,107 с |
| CPU процесса | 303,594 с | 11,344 с |
| Повторные проверки путей на этом этапе | 165 000 | 0 |

В этом прогоне подготовка ускорилась в 20.9 раза.

Команда воспроизведения: `python tools/benchmark_import.py --baseline-ref 7270b18 --files 55000 --service-records 20000 --runs 1`.

Это измерение подготовки метаданных. Оно не измеряет полное чтение 55 000 фотографий, скорость Яндекс.Диска или SMB. Память процесса и физический дисковый ввод-вывод в этом замере отдельно не измерялись. Переносимая опись с другого ПК по-прежнему не позволяет доверять кэшу проверки целостности: содержимое проверяется заново. На накопителе без надёжного признака изменения файла быстрая проверка также читает содержимое.

## Выполнено реально

- Основной набор: **482 passed, 1 skipped**, 250,06 с. Пропуск — права Windows на создание символической ссылки. Дополнительный актуальный набор регрессий 1.4.3: **8 passed**, включая исполнение счётчика в Node.js.
- Старый CMD runtime: Python 3.14.3, SQLite 3.50.4, **19 passed**. Проверено чтение и запись в режиме rollback journal: большие пакеты импорта не удерживают блокировку чтения во время записи в ту же базу.
- Ruff: проверки ошибок синтаксиса и неопределённых имён; Bandit: замечаний высокой серьёзности нет. JavaScript проходит `node --check`. Ручной просмотр включал импорт и сохранение описи, пути и коллизии, повторное использование копий, частичные загрузки, удаление превью, отчёты, восстановление и локальные HTTP-маршруты. Это не доказательство отсутствия всех возможных ошибок.
- Настоящий Windows EXE 1.4.3, сборка `20261021.1`: запуск без Python в PATH, версия и исправленная SQLite, встроенная статика, CSRF, выбор папки, прерванная история и ожидание очереди.
- Выход настоящего EXE через HTTP-интерфейс, сообщение нативному трею и закрытие мини-окна. Процессы завершились, порт и блокировка истории освобождены. Повторный запуск восстановил существующее мини-окно.
- В настоящем EXE подготовлены сведения о 1 000 тестовых файлах и сохранена опись. Счётчик — 1 000 файлов. SHA-256 всех файлов совпадает; опыт занял 2,243 с вместе с запуском.
- 47 встроенных модулей EXE соответствуют текущему коду. Личных абсолютных путей в кодовых объектах проекта нет.
- Нативные элементы управления проверены синтетически при 100/150/200/400%, включая повторные изменения масштаба и освобождение GDI-ресурсов.
- Настоящий первый запуск `start.cmd` создал новое виртуальное окружение и установил зависимости; сервер 1.4.3 запустился и завершился с кодом 0. SQLite 3.50.4; 30,759 с вместе с установкой. Пользовательская история не использовалась: отдельные папка состояния и порт.

## Ограничения проверки

Физический NAS, живой аккаунт Яндекс.Диска, полный объём большой фототеки и суточная выкачка в этом прогоне не проверялись. Проверки выполнялись на искусственных данных. Матрица GitHub Actions этой версии ещё не запускалась. Первичная установка CMD проверена на текущей Windows с новым окружением, а не на отдельном чистом компьютере.

Проверка целостности остаётся настоящим чтением файлов, если использовать прежний результат проверки безопасно нельзя. Зависший системный вызов Windows может задержать окончательное завершение операции, даже когда интерфейс уже принял остановку. Обновление не требует удаления скачанных копий или старой описи.
