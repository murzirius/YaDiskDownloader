# Архитектура

## Процесс и состояние

Waitress обслуживает только IPv4 loopback. Flask выдаёт статический интерфейс и JSON API. JavaScript хранит токен лишь на время передачи POST, очищает поле до отправки и не использует localStorage/sessionStorage для токена. В localStorage есть только признак просмотра инструкции. Credentials хранит токен, поколение соединения и активные HTTP-ответы; отключение отзывает поколение и закрывает ответы. requests не использует настройки proxy/.netrc из окружения и не отключает проверку сертификатов.

SQLite работает в WAL. `jobs` содержит настройки и фазу; `entries` — уникальные пары задания и исходного пути, метаданные, смещение обхода, исходы попыток; `artifacts` — подтверждённые результаты, размер, локальный SHA-256 и отпечаток метаданных; `names` — соответствие исходных и локальных имён с уникальностью casefold; `scan_errors` — ошибки обхода. Временные URL исключаются при сохранении метаданных. Токен никогда не входит в настройки задания.

Начальные выбранные пути нормализуются. Для каждого каталога API запрашивается страницами по 200 ресурсов до окончания `_embedded.total`; если total отсутствует — до пустой страницы. Элементы страницы и новое смещение сохраняются одной транзакцией. Очередь извлекается из SQLite порциями по числу потоков; полный список коллекции не хранится в памяти. Интерфейс имеет независимый размер страницы 100.

## Фазы

`new → scanning → ready → downloading → packing → completed / completed_with_errors`.

Пауза сохраняет исполняемую фазу в контроллере. Остановка переводит незавершённые записи в `cancelled`. После аварийного перезапуска активная фаза становится `interrupted`, записи `running` — `pending`; токен отсутствует. Продолжение перепроверяет метаданные всех файлов сформированной очереди. Повтор неудачных ограничивается ошибками, отсутствующими превью, заменами и неудачными папками. Пересборка ZIP не требует токена.

По одному исходному файлу фиксируется ровно один итог очереди. Оригинал и превью имеют отдельные исходы. В режиме приоритета оригинала успешный оригинал прекращает ветку превью. При восстановлении уже сохранённое превью исключается из текущего манифеста, если оригинал стал доступен; локальная историческая копия остаётся нетронутой.

`percent = processed / files` после сканирования. В processed входят `done`, `existing`, `partial`, `error`, `no_preview`, `cancelled`. Повторы и скачивание второго результата не увеличивают processed. Фазы и счётчики показывают полноту отдельно от процента. Сетевые байты включают повторные передачи, сохранённые байты — только текущие подтверждённые артефакты. Средняя скорость считается с начала текущего запуска, без времени паузы; это не мгновенная скорость.

## Файлы и имена

Новое задание получает новый корневой каталог, дозагрузка использует выбранный прежний; имя служебной папки отчётов резервируется только для содержимого ZIP. Локальные отчёты и архивы создаются прямо в корне импорта. Источник `disk:/a/b/file.ext` отображается в `a/b/file.ext` независимо от того, выбран корень, папка a/b или сам файл. Пустые папки создаются при подготовке путей. Неизвестные и опасные компоненты не исполняются и не интерпретируются как локальные пути.

Перед скачиванием исходные пути сортируются бинарно. Обычные имена сохраняются. Недопустимые символы, хвостовые точки/пробелы, устройства Windows и слишком длинные компоненты получают суффикс SHA-256 от исходного пути. Коллизии после casefold разрешаются суффиксом от идентификатора. Маппинг сохраняется в SQLite и повторно используется; одинаковые пути и порядок исходного списка дают одинаковое отображение. Превью резервируют отдельное имя после определения фактического формата. Если оно совпадает с исходным файлом, добавляется суффикс.

`safe_join` запрещает абсолютные локальные пути, `..`, `:`, обратный слеш и выход за разрешённый корень после разрешения ссылок. Каждый существующий компонент проверяется на symlink/junction. На Windows используются `\\?\`-пути; компоненты сокращаются до безопасной длины, общий путь ограничен пределом файловой системы. Экстремально глубокий путь становится ошибкой соответствующего файла, а не записью за пределами корня.

Блоки пишутся во временный `.part`, одновременно считаются MD5 и SHA-256. После fsync сравниваются Content-Length, размер из метаданных и доступные контрольные суммы оригинала. Превью проверяется Pillow, определяется формат и декодируется для проверки целостности. На Windows целевой файл создаётся через os.rename, который отказывает при существующем имени; на POSIX используется hard link без замены. SQLite подтверждает результат только после проверки и сохранения. При аварии между созданием целевого файла и фиксацией SQLite он не будет ошибочно признан подтверждённым: следующая попытка использует другое имя.

Проверенные артефакты пропускаются только при совпадении актуального отпечатка метаданных, размера, локального SHA-256 и размера превью. Старые версии и чужие файлы не перезаписываются. Во время скачивания состояние файла может измениться; несовпадение метаданных/байтов не получает статус успеха. Перезапуск продолжает файл с начала, а не через HTTP Range. Временные файлы создаются через mkstemp в корне импорта на том же томе, чтобы завершение оставалось атомарным, и удаляются после каждой попытки. Незавершённые части после аварийного выключения могут оставаться в корне, но не попадают в ZIP.

## HTTP и ограничения

Разрешены только GET `/resources` и `/resources/download`. API-запросы всегда идут на фиксированный cloud-api.yandex.net. Медиа-ссылки извлекаются из ответа API и проверяются до каждого перенаправления. OAuth для оригиналов не отправляется на временную ссылку: используется подписанный URL. Для приватных превью он допустим только на фиксированных downloader-хостах Яндекса. Сторонний редирект или неизвестный хост отклоняется. Ошибки HTTP формируются из статуса, без вывода upstream body, URL или содержимого исключения requests.

Повторы ограничены настройками: запросы метаданных при обходе имеют ограниченный бюджет; получение ссылки, редиректы и потоковая передача файла разделяют одну попытку, без вложенных повторов. Сетевая ошибка, 429 и 5xx получают backoff; Retry-After поддерживает секунды и HTTP date. Ограничение API устанавливает общую паузу новых запросов для потоков. 403/401 временной ссылки вызывают получение свежей ссылки в следующей потоковой попытке. 401 основного API останавливает задание, требуя нового токена.

## Отчёты и ZIP

Все форматы сериализуют общий summary и одинаковый поток записей: исходный путь, локальный путь, статус, ошибка, исходы попыток, переход к превью, список результатов с типом/размером/SHA-256. Ошибки обхода имеют `record_type=scan_error`. Отчёты включают нескачанные файлы. CSV содержит summary отдельной записью и ту же схему полей; `results` сериализуется JSON в одной ячейке. Опасные для Excel значения получают ведущий апостроф.

Отчёты сохраняются как report-<generation>.<format>, архив — result-<generation>.zip непосредственно в корне импорта. Имена резервируются в names с проверкой всех исходных имён и существующих локальных файлов; коллизии получают суффикс, перезаписи нет. В ZIP отчёты отображаются отдельно в __disk_service_<id>/reports/report.<format>. Упаковка перечисляет каталоги из маппинга и только текущие artifacts плюс выбранные отчёты; произвольный обход папки результата не выполняется. Архив читается/пишется блоками по 1 МиБ, ZIP64 принудительно разрешён для файлов, сжатие отключено. Во время упаковки заново проверяются размер и SHA-256 результата. ZIP `.part` становится доступным только после завершения без ошибок. Прогресс ZIP — фактически упакованные исходные байты относительно суммы файлов/отчётов; фактический конечный размер включает заголовки и структуры ZIP.

Отчёты описывают итог скачивания и не содержат размер будущего архива, который ещё неизвестен в момент их записи. Его точное значение сохраняется в jobs и показывается после упаковки. Ошибка упаковки имеет отдельную фазу failed; уже скачанные результаты и отчёты сохраняются, ZIP можно пересобрать.


Для каждой попытки используется Deadline на монотонном времени. HTTPAdapter не выполняет автоматические повторы; пул регистрирует соединения в Deadline до чтения заголовков. Контрольный поток отключает сокеты после истечения бюджета, в том числе при медленной подаче заголовков/тела. После получения ответа отслеживается также сокет HTTPResponse. Активные паузы вычитаются из часов попытки. urllib3 закреплён на проверенной версии 2.8.0, поскольку отслеживание сокетов использует детали транспорта. Системные операции DNS/дискового ввода-вывода могут завершать свой текущий вызов; после возвращения истёкшая попытка не получает статус успеха.

Дозагрузка создаёт новое задание в существующем корне, наследует names/artifacts из прежнего задания или переносимого import_state. Очередь сканируется заново. Артефакты сравниваются со свежими метаданными и локальными хешами; устаревшие удаляются из текущего манифеста, а их локальные файлы сохраняются. Сводка и ZIP используют JOIN artifacts с текущими entries, поэтому исчезнувшие с Диска файлы остаются локально, но не добавляются в новый ZIP. Переносимое состояние записывается атомарно в .disk-import*.sqlite3 при подготовке и завершении операции.

Интерфейс не содержит ссылки, запускающей браузерное скачивание результата. POST open-output с CSRF открывает корень задания в Проводнике. Готовый ZIP уже находится там. Старый потоковый download API сохранён для совместимости, но не вызывается автоматически или кнопкой папки.
## Очередь повторной загрузки и производительность

Новые задания используют 8 потоков, 1 попытку и 20 секунд на попытку. Дозагрузка и повтор уже упакованного задания действуют как приоритет оригинала: актуальный оригинал исключает новую загрузку превью, а имеющееся превью допускает попытку оригинала. При продолжении незавершённого задания уже проверенный оригинал также исключает новое превью. Старые файлы не удаляются.

Сначала пул обрабатывает записи без сохранённых артефактов, чтобы они не ждали проверки большого прежнего импорта. Затем прежние артефакты проверяются по размеру и SHA-256; недействительные становятся первыми в оставшейся очереди, за ними идут источники только с превью, последними — источники с оригиналом. Индекс queue_priority поддерживает выдачу очереди без загрузки её целиком в память. Результат проверки кешируется в SQLite только для текущего запуска; подпись включает идентификатор файла, размер, время изменения и SHA-256. При изменении подписи хеш проверяется заново. После перезапуска кеш очищается.

Первая попытка превью использует свежие метаданные, уже полученные при обработке источника. Повторная попытка снова получает ссылку, поэтому истечение ссылки не закрепляется кешем. Прогресс передачи записывается в SQLite порциями до 1 МиБ или раз в 250 мс, упаковки — до 4 МиБ или раз в 250 мс; остаток записывается и при ошибке. Режим WAL задаётся один раз при инициализации базы. Строки отчёта получаются потоковым LEFT JOIN без отдельного соединения для каждого файла.

Engine.status добавляет объём актуальных файлов, зарегистрированных служебных результатов и активных временных файлов. Для этого не выполняется рекурсивный обход дерева при каждом опросе. Свободное место берётся из disk_usage. Исторические версии исходников и посторонние файлы не входят в счётчик; размеры файлов могут отличаться от выделенных файловой системой блоков.

Первое открытие интерфейса показывает локальную инструкцию из трёх шагов. В localStorage сохраняется только признак её просмотра, без токена и ClientID. Введённый ClientID проверяется и используется для ссылки на официальный Яндекс OAuth; токен пользователь вводит отдельно в локальное поле. Инструкция доступна повторно по кнопке «Как начать».

## HTML-журнал

Journal записывает события в journal_events SQLite с индексом (job,id); авторизация и временные ссылки удаляются перед вставкой. Очередь событий сохраняется между продолжениями и перезапусками. На новую операцию создаётся отдельный поток сохранения с интервалом 300 секунд монотонного времени, работающий также на паузе. При завершении поток останавливается и выполняется последняя запись.

Снимок log-<id>.html сохраняется атомарно в корень импорта, независимо от отчётов. Имя резервируется, принадлежность существующего файла проверяется маркером; чужой файл сохраняется, выбирается новое имя. Состояние журнала и ошибки записи доступны в API задания. Ошибка записи журнала не прерывает скачивание. HTML не включается в ZIP результатов. События читаются из SQLite потоком до фиксированного максимального id; в браузере показаны только 50 строк за раз, все события остаются в JSON внутри HTML. HTML и JavaScript работают автономно, используют textContent и экранирование JSON для защиты имён файлов. Кнопка открытия использует локальный файл, без загрузки в каталог браузера.

## Возможности 1.1

Настройки create_zip, auto_pause, max_disk_percent, adaptive_workers и resume_parts имеют совместимые значения по умолчанию для старых заданий. Без ZIP записываются обычные отчёты и увеличивается поколение результата; ручная упаковка доступна позднее. Повтор выбранных файлов проверяет принадлежность путей заданию и ограничивает SQL-очередь выбранными источниками, включая задания с другими необработанными файлами.

Control.check проверяет процент занятости тома назначения не чаще двух раз в секунду и ставит общую паузу. Все рабочие потоки используют этот checkpoint, пауза исключается из Deadline. Причина отображается в API и журнале. При продолжении проверяется текущий порог; его можно изменить на живой паузе. Проверка имеет дополнительный нижний запас свободного места 8 МиБ. AdaptiveWorkers ограничивает подачу новых задач в пул с фиксированным максимумом: сетевые ошибки уменьшают лимит, стабильные результаты постепенно повышают его; устойчивое падение скорости учитывается по нескольким окнам. Уже запущенные передачи не прерываются при снижении лимита.

Partials хранит локальное имя, отпечаток источника, подтверждённую длину, SHA-256 префикса, строгий ETag и полный размер. Периодические checkpoints выполняют flush/fsync до записи длины и хеша в SQLite. При продолжении префикс перепроверяется, неподтверждённый хвост отбрасывается. Range и If-Range отправляются только на свежую ссылку медиа, без заголовков на запрос метаданных. Для 206 проверяются Content-Range, длина и ETag; ответ 200 начинает файл заново. Полный оригинал проверяется по метаданным и контрольным суммам. Превью продолжаются только с сильным ETag. Части входят в переносимый манифест; старые манифесты без таблицы частей поддерживаются. Чужая изменённая часть сохраняется, вместо неё создаётся новый временный файл.

Profiles и Preferences находятся в локальной базе. Профили проходят белый список validate_settings, не включают токены и пути служебных файлов. Updates запрашивает только GitHub API по HTTPS, без авторизации Яндекса, с бюджетом 8 секунд; автоматическая проверка ограничена одним успешным или неуспешным запуском в час на процесс. Версия сравнивается по тегам vX.Y.Z, пользователю показывается ссылка на релиз.

Диагностика создаёт самостоятельный ZIP в корне импорта: окружение, разрешённые параметры, агрегаты, до 1000 ошибочных источников и 2000 последних событий. Свободный текст ошибок преобразуется в категории; имена и пути заменяются идентификаторами, ключи и временные ссылки не экспортируются. Контент файлов, SQLite и профили не копируются. API предварительного просмотра не создаёт архив. Файлы диагностики не включаются в ZIP результатов.

## Категории и ETA

file_types.py определяет группу по media_type, MIME и расширению. Store.insert_entry фильтрует только файлы и сохраняет категорию в безопасных метаданных; каталоги не фильтруются, смещение страницы всегда увеличивается по всем полученным элементам. Process перепроверяет категорию по свежим метаданным; изменившийся неподходящий источник получает статус filtered. Для музыки и других файлов используется ветка originals без запроса превью. Артефакты исключённых типов остаются для будущих импортов, но JOIN текущей очереди не допускает их в ZIP.

RemainingTime хранит ограниченную выборку времени, переданных байтов и обработанных источников, с окном около 30 секунд. Старт скачивания и старт ZIP создают разные выборки. Engine.status получает оставшийся объём из SQLite, учитывает принятые байты активных оригиналов и известные размеры активных превью. При неизвестном объёме применяется темп обработки файлов. До накопления данных, при паузе и остановке возвращается null; после завершения — 0. Значение относится к текущей фазе, не является обещанием срока завершения.
