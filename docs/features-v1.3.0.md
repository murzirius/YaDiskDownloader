# Функции 1.3.0

Ручное подключение своим токеном сохранено. Единое OAuth-приложение проекта и автоматический вход через Яндекс не добавлялись.

## История и очередь

«Инструменты → История» показывает страницы по 30 задач с поиском и фильтрами. Удаление записи не удаляет результаты. Активное или стоящее в очереди задание нельзя архивировать или удалить. Сначала завершите работу и уберите его из очереди.

«В очередь» добавляет подготовленное задание. Очередь выполняется последовательно и хранится в SQLite. Пауза очереди не прерывает текущую задачу. Если она остановлена или завершилась ошибкой, очередь приостанавливается; решите проблему, уберите проблемную запись из очереди и добавьте её снова либо продолжите очередь для остальных задач. После перезапуска загрузки ждут ручного подключения токеном.

## Локальная проверка и очистка

Проверка работает по артефактам в истории или `.disk-import*.sqlite3` в папке. Она читает содержимое и сравнивает SHA-256, не обращается в облако и не меняет пользовательские файлы. Если опись отсутствует, неизвестно, какие файлы должны присутствовать. Список проблем в интерфейсе ограничен 2000 записями; счётчики охватывают все проверенные результаты. «Подготовить дозагрузку» заполняет папку и список проблем, а запуск выполняет пользователь после подключения.

Очистка рассматривает только временные файлы, зарегистрированные этой установкой, старше часа. Неподтверждённые чужие `.part` не удаляются. Части для продолжения, намерения публикации, папки активных и ожидающих задач защищены. Перед очисткой показываются имена и объём; перед действием сверяется состояние файлов. Используется современная корзина Windows без перехода к обычному удалению.

## Отчёты и аварийное завершение

Для каждого выбранного формата отчёта используется один файл в папке. Старые нумерованные отчёты из 1.2.x сохраняются на месте. В 1.3.0 создаются собственные постоянные файлы. Программа заменяет только служебный файл с подтверждённым содержимым; изменённый вручную файл сохраняет и резервирует другое имя.

SQLite использует WAL и synchronous=FULL. Подтверждённая часть файла записывается с flush/fsync перед сохранением её размера и SHA-256. Перед перемещением проверенного файла сохраняется намерение публикации; после аварии подтверждённый результат регистрируется без повторной загрузки. На Windows MoveFileExW используется с WRITE_THROUGH. Отчёты пишутся во временный файл и заменяются атомарно. На время упаковки фиксируется согласованный снимок отчётов; журнал продолжает обновляться. Повреждение носителя и потеря данных, которые оборудование не записало, не могут быть полностью исключены приложением.

## Резервные копии

Копии создаются через SQLite backup API, учитывающий WAL. Перед первым запуском новой версии сохраняется before-версия.sqlite3; сохраняются последние пять автоматических копий. Ручные копии ограничены последними десятью файлами. Импортированная копия проверяется на целостность и нужные таблицы; при восстановлении данные копируются в известную схему, чужая SQL-схема не выполняется. Восстановление запрещено при активной операции, создаёт копию текущего состояния, очищает подключение и приостанавливает очередь. Внешние копии не передают доверие к кэшу проверки и владению файлами.

## Обновление и уведомления

Скачивание получает Windows ZIP из выбранного публичного репозитория GitHub и проверяет digest SHA-256 из GitHub API. Это проверка целостности архива, не цифровая подпись издателя. Не меняйте репозиторий обновлений на источник, которому не доверяете.

Установка доступна в EXE на Windows и только при отсутствии активной работы. Помощник запускается из копии текущего EXE, дожидается выхода программы, заменяет EXE и ждёт подтверждения версии и работающего локального сервера. При неудаче восстанавливает предыдущий EXE и согласованную копию базы. Папки результатов не перемещаются. Отсутствие места, права записи или занятый EXE приводят к отказу с сохранением старой установки.

Уведомления Windows содержат только состояние задачи, без личных путей и токена. При нажатии открывается локальное приложение. Тихий режим и разрешения Windows могут скрывать уведомления. Отключение доступно в окне версии.

## Автоматические проверки

Workflow `.github/workflows/checks.yml` проверяет Windows/Linux и Python 3.11/3.14. Выпуск по тегу vX.Y.Z требует совпадения с версией приложения и успешных тестов; затем собирает и публикует два архива и контрольные суммы. Архив исходников собирается по списку разрешённых файлов, без окружения, истории, результатов и токенов. Workflow выполняется после его добавления в GitHub.
