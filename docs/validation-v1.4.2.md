# Проверка YaDiskDownloader 1.4.2

## Исправленные проблемы

| Проблема | Результат исправления |
| --- | --- |
| Недоступная папка могла привести к потере записи о ранее скачанной копии | Задание приостанавливается. Запись и файл сохраняются до восстановления доступа к той же папке. |
| Проверка сетевого накопителя могла надолго задержать рабочую операцию | Проверки выполняются в отдельных потоках: не более двух незавершённых проверок на процесс, с ограниченным ожиданием и отменой ожидания при остановке. |
| Запуск после аварии мог завершиться ошибкой резервного копирования SQLite | Перед снимком база открывается для штатного восстановления. На Windows краткая ошибка SQLITE_IOERR_TRUNCATE повторяется не более трёх раз с общим ожиданием 0,7 с. Постоянная ошибка остаётся ошибкой. |
| Ошибка запуска рабочего потока оставляла неподвижное задание | Задание получает состояние, из которого можно продолжить; несуществующий поток больше не удерживает управление. |
| На паузе скачивания мог отображаться уже завершённый счётчик проверки папки | Счётчик проверки показывается только на соответствующем этапе. |
| Обрыв связи с NAS при автономной проверке мог выглядеть как пропавшие файлы | Проверка завершается с причиной недоступности папки; незавершённый результат нельзя использовать как готовый список для восстановления. |
| Неожиданная ошибка автономной проверки могла остаться без объяснения | Ошибка отображается, а блокировка инструментов проверки снимается. |
| Запланированное ожидание источника или ограничение скорости могли выглядеть как зависание | Предупреждение учитывает реальные изменения прогресса и запланированные ожидания. |
| Предупреждение об отсутствии прогресса могло не попасть в уведомления без изменения БД | Проверка предупреждения работает и без новых записей SQLite. |
| Повтор ошибок затрагивал успешно сохранённые превью | Новая команда выбирает только неудачные файлы через временную выборку в SQLite; получение оригиналов вынесено в отдельное действие. |
| Ограничения FIPS могли запретить сверку MD5, предоставленного API | MD5 явно используется как проверка совместимости, а проверка SHA-256 остаётся обязательной. |
| Повторный запуск EXE не возвращал уже открытое окно | Существующий экземпляр активируется через локальный API с обычной проверкой CSRF и совпадением папки состояния. |
| Большой журнал задерживал поиск и создавал лишние промежуточные данные | Экспорт читает события нужной папки и сериализует их порциями; поиск уступает управление интерфейсу и отменяет устаревший запрос. |

## Выполненные проверки

Полный прогон: **475 тестов пройдено, 1 пропущен, ошибок нет; 376,48 с**. Пропущен тест создания символической ссылки: Windows не разрешила создать её в тестовой папке. Остальные проверки ссылок и границ пути не отключались.

- Принудительное завершение отдельного процесса во время обхода, загрузки, публикации файла, отчётов и ZIP. После запуска проверяются целостность резервной копии, продолжение и содержимое результатов.
- Имитация недоступного NAS, замены папки по тому же пути и заблокированной проверки накопителя. Проверены сохранность описи, ограничение фоновых проверок, остановка и продолжение.
- Реально собран и запущен Windows EXE 20261020.3. Проверены запуск без установленного окружения проекта в PATH, системный выбор папки, повторный запуск и восстановление существующего окна, прерванная история и ожидание очереди.
- Выход из EXE через HTTP, трей и мини-окно: порт и блокировка состояния освобождаются, дочерние процессы завершаются.
- Перенос истории в настоящем EXE: 1 000 файлов, 3 002 записи, сохранение описи и проверка SHA-256 всех файлов.
- CMD реально запущен через `start.cmd` в новом окружении Python: зависимости установлены, сервер запустился и завершился с кодом 0. Первый запуск с использованием доступного кэша пакетов — 46,6 с, повторный — 2,25 с. Использовался системный Python с SQLite 3.50.4. Это не проверка установки на чистой Windows.
- 47 встроенных модулей проекта сопоставлены с текущими исходниками. Личных путей к исходникам в именах этих модулей нет.
- 20 переключений DPI-событий между 100%, 150% и 200%: контролы помещаются в окно, шрифты масштабируются, число GDI-ресурсов не растёт. Настройки дисплея Windows не изменялись.
- Ruff: проверки F/E9 пройдены. Bandit: нет предупреждений высокой серьёзности; места сборки SQL проверены вручную. Это не доказательство отсутствия всех уязвимостей.

## Измерение HTML-журнала

Одинаковый синтетический сценарий на локальном диске: 50 000 событий нужной папки и 100 000 событий другой папки. По три чередующихся прогона 1.4.1 и 1.4.2, ниже медианы. Подготовка данных не входит в замер; `tracemalloc` включён в обоих вариантах.

| Показатель | 1.4.1 | 1.4.2 |
| --- | ---: | ---: |
| Сохранение журнала | 1,782 с | 1,136 с |
| CPU процесса при сохранении | 1,766 с | 1,125 с |
| Пиковые выделения Python | 2 321 395 Б | 2 326 684 Б |

В этом сценарии время и CPU сократились на **36,3%**. Дополнительные 5 289 Б пиковых выделений Python связаны с порционной сериализацией. Это замер выделений Python, а не всей оперативной памяти процесса, кэша ОС или памяти SQLite. Файл содержит всю историю соответствующей папки; функциональность журнала не урезалась. Результат не следует переносить на скорость сети или произвольный NAS.

## Что остаётся проверить

Реальный сетевой NAS, отключение накопителя во время физической записи, живой аккаунт Яндекс.Диска и перенос окна между физическими мониторами с разным DPI в этом прогоне не проверялись. Автоматический тест DPI не заменяет визуальную проверку на таких мониторах.

Ограниченное ожидание проверки накопителя не отменяет уже зависший системный вызов Windows. При задержке чтения или записи интерфейс принимает запрос паузы или остановки, но завершение самой операции может ждать ответа ОС. Приложение не запускает вторую копию задания поверх занятой операции.

Основной набор тестов и EXE проверены локально на Windows, Python 3.14.8 и SQLite 3.51.3; отдельный CMD-прогон использовал системный Python с SQLite 3.50.4. Матрица Python 3.11/3.14 и Linux настроена в GitHub Actions; удалённые проверки этой сборки ещё не запускались. Проверка на полностью чистой Windows без установленного Python не выполнялась.
