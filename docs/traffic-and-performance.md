# Трафик и скорость работы

## Что работает автоматически

- Миниатюра, которую уже открывали, берётся из памяти. Кэш ограничен 32 МБ, действует до двух минут и очищается при смене подключения. После обновления списка изменённый файл получает новую миниатюру.
- Для списка файлов запрашиваются только нужные сведения. Размеры, контрольные суммы, даты и данные для превью сохраняются.
- Для JSON приложение запрашивает gzip и повторно использует соединения. Загрузки файлов и запросы продолжения Range работают без сжатия.
- Интерфейс получает изменения состояния вместо повторной передачи всех настроек. При пропущенном обновлении приходит полный ответ.
- Одинаковые вспомогательные сведения не записываются в SQLite повторно. Сохранение готовых файлов и контрольных точек частей осталось обязательным.

## Где настроить

Откройте **«Инструменты → Трафик»**. Здесь показаны полученные данные за день, число запросов, кэш и замеры ожидания сервера и получения данных. Время потоков суммируется: оно может быть больше времени по часам. Подсказка о причине задержки приблизительная.

**Дневной лимит** задаётся в МБ. 0 отключает ограничение. Считаются данные Яндекс.Диска: файлы, миниатюры и ответы JSON с учётом сжатия. Проверка и загрузка обновлений программы из GitHub в этот счётчик не входят. Заголовки, TLS и другой сетевой трафик сюда не входят. Это не счётчик провайдера. Несколько уже начатых чтений могут закончиться после достижения лимита. После резкого завершения процесса учёт использует запас до 1 МБ, чтобы не забыть уже полученные данные.

Когда лимит достигнут, задание встаёт на паузу. Увеличьте лимит или дождитесь следующего дня, затем нажмите **«Продолжить»**.

В дополнительных настройках загрузки:

- **Потоки проверки файлов на устройстве** — отдельно от потоков скачивания. Для обычного жёсткого диска начните с 1–2, для SSD или сетевого хранилища можно выбрать 4. Проверка контрольных сумм сохраняется.
- **Экономия запросов** использует сведения из только что подтверждённой страницы для оригиналов с SHA-256. Срок — до минуты, объём ограничен общим кэшем. Старые сведения и сведения без SHA-256 не используются. Перед скачиванием превью источник запрашивается заново.
- **Ранний старт** начинает скачивание подтверждённой страницы, пока остальные папки ещё не обойдены. Функция выключена по умолчанию. Она действует для новой загрузки без поиска дубликатов, приоритетных папок и отложенного запуска. Дозагрузка сначала заканчивает проверку ранее сохранённых файлов. ZIP создаётся после завершения обхода и скачивания.

Кнопка **«Завершить текущие файлы и остановиться»** сохраняет файлы, которые уже скачиваются, и не начинает новые. Обычная кнопка остановки по-прежнему прерывает работу сразу и сохраняет доступные части.

В списке проблем можно повторить только файлы выбранной группы. Через поиск в инструментах можно найти настройку по словам «скорость», «потоки» или «ZIP».

## Установка Windows

Полностью распакуйте ZIP, запустите EXE и выберите **«Инструменты → Установить на ПК»**. Программа скопируется в папку приложений текущего пользователя и создаст ярлык в меню «Пуск». Права администратора не нужны. Отдельный установочный архив не требуется.

Это простая установка с ярлыком, без регистрации в списке приложений Windows. История, профили и скачанные файлы не перемещаются. Изменённые или посторонние файлы в папке установки не заменяются. Для удаления установленной копии закройте программу и удалите её папку и ярлык. Папки результатов и историю удалять не нужно.

## Проверки

Обычные тесты и сравнение производительности используют искусственные файлы и локальные серверы. Профиль сравнивает прежний и текущий код на одном сервере по трём чередующимся повторам. Время на общем сервере меняется от нагрузки; ухудшение более чем на 30% выводит предупреждение для повторной проверки. Целостность результатов, SQLite и предел памяти проверяются обязательно.

Проверка настоящего Яндекс.Диска запускается отдельно, только с тестовым аккаунтом и синтетическими файлами. Она не изменяет облако и не получает доступ к остальным папкам аккаунта. Результат без настроенного токена считается непроведённой проверкой. Сбой Яндекс.Диска или интернета отмечается отдельно от ошибки проверки приложения. Успех обычных тестов не означает, что настоящий Диск был проверен.
