# Продолжение аудита — 18 октября 2026

База: main, коммит 842510a. Исправления найдены чтением сетевых и файловых операций, обработки исключений и управления заданиями. Отдельные воспроизведения добавлены до изменения соответствующего кода. Это проверка перечисленных сценариев, а не гарантия отсутствия всех ошибок.

## Найдено и исправлено

| № | Приоритет | Ошибка | Исправление |
|---|---|---|---|
| 1 | P1 | Системный DNS блокировал запрос дольше лимита попытки и мешал остановке | Ожидание DNS проверяет отмену и лимит; не более 8 системных работ одновременно, без очереди фоновых заданий. Повторные запросы одного имени объединяются. Положительный кэш ограничен 128 записями и 30 секундами; после неудачи подключения запись удаляется |
| 2 | P1 | До завершения TCP-подключения таймер не видел сокет; TLS мог получить старый бюджет времени | Сокет зарегистрирован перед connect; перед TLS применяется оставшееся время. Проверку сертификатов и SNI выполняет прежний HTTPS-код urllib3 |
| 3 | P2 | Сбой запуска потока таймера оставлял запрос зарегистрированным в управлении сетью | Регистрация снимается при ошибке запуска |
| 4 | P2 | Пауза во время подготовки ZIP, описи или журнала требовала ключ Яндекса для продолжения, хотя операция локальная | Сервер и интерфейс учитывают тип операции; кнопка «Продолжить работу» доступна без ключа. Это также действует для автоматической упаковки после скачивания |
| 5 | P2 | При ошибке регистрации временного файла в SQLite созданный файл оставался на диске | Удаляется только что созданный временный файл; исходная ошибка передаётся вызывающему коду |
| 6 | P2 | После публикации результатов оставались строки temporary_files, учёт рос с количеством файлов | Исчезнувшие временные файлы снимаются с учёта. Для загрузок очистка включена в существующую транзакцию; сохранные части для докачки остаются |
| 7 | P1 | ZIP результата и архив диагностики публиковались без явного сброса содержимого на накопитель | os.fsync после закрытия архива и до публикации. Ошибка сброса не считается успешной публикацией. Это не гарантия от аппаратного сбоя или отключения питания |
| 8 | P2 | Неудачная пересборка ZIP сбрасывала ссылку на предыдущий готовый архив | Ссылка меняется только после успешной публикации нового ZIP |
| 9 | P2 | Сбой записи SQLite при подготовке ZIP или финальном сохранении прогресса пропускал очистку временного архива | Подготовка включена в область очистки; очистка выполняется и при ошибке записи прогресса. Удаляются временные данные текущей операции |

## Воспроизведения и измерения

- Первые восемь новых случаев упали до исправлений. Ещё два сценария ошибки SQLite при упаковке также сначала воспроизведены падением тестов. Итоговый файл tests/test_followup_audit.py содержит 19 регрессионных случаев, включая TLS, кэш DNS, остановку и паузу.
- Искусственно заблокированный DNS на 1,2 с, лимит попытки 0,1 с: возвращение запроса **1,202 с до → 0,1217 с после**. Сетевых обращений к Яндексу в этом опыте нет.
- При 12 отменённых ожиданиях и тестовом пределе 2 системных DNS-работы фактически осталось 2 работы, остальные не запускаются в фоне. В обычном режиме предел 8. Восемь одновременных запросов одного имени используют один DNS-вызов.
- Проверка 1000 уже готовых файлов: предыдущий контроль **1,703 с**, новый **1,8373 с**; оба — 3 соединения SQLite, 18 SELECT и 0 COMMIT. Ускорение локальной проверки этим изменением не заявляется; один замер не отделяет колебания среды от небольшого изменения времени.
- Реальные HTTPS-подключения без ключей через новый сетевой адаптер: GitHub API — HTTP 200 за 0,961 с; API Яндекс.Диска — HTTP 405 на HEAD за 3,685 с. Второй ответ подтверждает соединение и TLS, но не проверяет скачивание или авторизацию аккаунта.
- Локальный HTTPS-сервер с временным сертификатом: доверенный сертификат и правильное имя принимаются, неправильное имя и недоверенный сертификат отклоняются; SNI сохранён.
- Принудительное завершение процесса и восстановление на итоговом коде: 5 циклов по 700 файлов, 5 принудительных завершений, искусственная потеря связи в каждом цикле; во всех циклах SHA-256 всех файлов совпал, SQLite integrity_check = ok. Пиковый RSS процесса — до 56,1 МБ. Длительность — 65,92 с; это не ночной нагрузочный прогон.
- В браузере проверено продолжение автоматической упаковки после паузы и удаления тестового ключа: задание завершено, оригинал сохранён, ZIP создан. Проверка изолирована от пользовательских данных.

## Проверка сборки

Настоящий Windows EXE пересобран после последних исправлений и запущен дважды. Проверены локальный выбор папки, история прерванного задания после запуска, ожидание очереди, актуальные файлы интерфейса, CSRF, выход через веб-интерфейс и нативное событие закрытия трея. В обоих случаях дочерние процессы завершились, порт и блокировка состояния освобождены. Запуск занял 2,86–2,91 с, выход — 2,51–3,35 с. Встроенная SQLite 3.51.3, безопасный WAL включён.

Итоговый полный прогон Windows, Python 3.14.8: **410 passed, 1 skipped за 184,78 с**. Пропуск — символическая ссылка без нужных прав Windows; проверка сертификатов действительно выполнена. Все 19 новых случаев и существующая проверка неизменности отчётов во время упаковки также прошли отдельный прогон: 20 passed за 7,80 с. Существующая проверка поймала регрессию в промежуточном варианте очистки ZIP; переход к упаковке возвращён под REPORT_LOCK, чтобы фоновый отчёт не менял снимок архива. Эта промежуточная регрессия не считается ещё одной ошибкой исходной версии. Свежий CMD-архив отдельно не собирался, матрица GitHub Actions для этих локальных изменений не запускалась.

## Ограничения

Сам системный getaddrinfo нельзя безопасно прервать в потоке Python. После отмены приложение перестаёт ждать, а системный вызов может завершиться позднее; число таких вызовов ограничено. Если зависнут все 8, новые запросы будут ждать свободного места с соблюдением своего лимита и отмены. Не добавлены вечные фоновые повторы или отключение проверки TLS.

Не проверялись реальный аккаунт и большая загрузка с Яндекс.Диска, ночь работы, настоящий BSOD, отключение питания, неисправный диск и все сетевые накопители. Зависшие системные файловые операции остаются зависимыми от Windows. У большого самостоятельного HTML-журнала по-прежнему нет отдельного нагрузочного замера браузерной памяти.

Версия публичного релиза в рамках проверки не меняется. Проверочная сборка не является новым GitHub Release.
