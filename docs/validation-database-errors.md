# Проверка диагностики ошибок базы

Обновлённая сборка 1.4.3: номер 20261021.5. Проверки ниже сначала выполнены на диагностической сборке 20261021.4; сборка 20261021.5 использует те же исправления и упрощённые объяснения ошибок.

## Изменения

- Ошибки фоновых заданий сохраняются в технический журнал до завершающих операций. В диагностике есть этап, номер ошибки, код SQLite и место сбоя в коде.
- Текст SQLite классифицируется без публикации исходного сообщения: оно может содержать имена файлов, пути и другие личные данные.
- Ошибка сохранения описи больше не скрывает исходную ошибку задания.
- В верхней панели появилась отдельная кнопка «Диагностика» и пояснение, что означает ошибка истории и как сохранить сведения о ней.
- Проверка фоновой ошибки SQLite в настоящем EXE добавлена в GitHub Actions; используются только искусственные данные.

## Проверка настоящего EXE

На искусственной описи без одного из нужных столбцов вызван `SQLITE_ERROR` при подготовке дозагрузки. В прежнем EXE 20261021.3 технический список ошибок оставался пустым. В сборке 20261021.4 сохраняются причина `missing_column`, этап `preparing`, номер ошибки и строки кода. Содержимое тестового файла и исходная опись при сбое не меняются.

После исправления только тестовой описи повторная операция завершилась успешно. Проверка базы `quick_check` вернула `ok`.

Дополнительно запущен настоящий EXE с импортом истории 1000 тестовых файлов: файлы сохранились, SHA-256 совпал, опись записана. Проверены запуск, выбор папки, восстановление истории, выход через браузер, трей и мини-окно, завершение дочерних процессов и освобождение порта. Код 47 модулей EXE совпадает с исходным кодом; личных абсолютных путей в именах исходников нет.

Локальный полный прогон: **507 тестов пройдено, 1 пропущен** (для создания ссылок нужны дополнительные права Windows), ошибок и падений нет. Время — 252,44 с. Проверка Ruff и синтаксиса JavaScript пройдена.

## Ограничения

Искусственная ошибка проверяет сбор диагностики и возможность повторного запуска. Она не доказывает устранение других причин `SQLITE_ERROR`. Не проводились проверки на реальном аккаунте Яндекс.Диска, пользовательской базе или физическом NAS. Ошибки фоновых заданий, возникшие до установки этой сборки, восстановить из одного общего кода невозможно. ZIP диагностики следует сохранять до перезапуска приложения.
