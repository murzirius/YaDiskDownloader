# Проверки надёжности — 1.5.0, сборка 20261023.1

Проверки выполнены 23 октября 2026 года на Windows 11, Python 3.14.8 x64 и SQLite 3.51.3. Использовались синтетические файлы, изолированные базы, локальный HTTP-сервер и управляемые отказы. Реальные ключи Яндекса и пользовательские загрузки не использовались.

## Исправления

- Ошибка записи вспомогательного кеша SQLite после успешного сохранения файла больше не превращает загрузку в повтор или ложную ошибку. Проверка самого файла сохранена.
- Команды и диагностика привязаны к выбранному заданию. Устаревший ответ после переключения задания или закрытия диалога не применяется к другому заданию.
- Профили восстанавливают все параметры; сохранение расписания без изменения даты не теряет секунды и точность времени.
- Повреждённая запись настроек или описи обрабатывается отдельно. Исправные соседние записи остаются доступны, исходные повреждённые данные сохраняются для восстановления.
- Ожидание SQLite при резервном копировании и записи ограничено и поддерживает отмену. Восстановление не удерживает общий файловый замок на время долгой операции.
- Предпросмотр очистки не обращается к посторонним накопителям под общим замком. Сохранена защита старых ссылок на файлы.
- Исправлены лишняя сериализация запросов только для чтения, повторные вычисления путей в отчётах и повторный разбор настроек уведомлений.
- Изменённые или чужие описи не перезаписываются: новой описи выделяется отдельное имя.
- Восстановление после прерывания публикации файла принимает только подтверждённую пару временного и конечного файла. Неизвестные ссылки и неоднозначные состояния отклоняются.
- Ограничение скорости в тихие часы сохраняется при изменении числа потоков. Настройки уведомлений применяются одинаково к состоянию и ошибкам задания.
- Исправлен повторный запуск проверки приложения после отказа создания потока.
- Укреплены предварительная проверка обновления Windows, копирование, откат и повторный запуск. Очистка старых обновлений сохраняет активные, изменённые и неизвестные файлы.
- Внутренние пути обновлений и резервных копий поддерживают длинные пути Windows. Частные временные копии SQLite нормализуются без изменения журнала действующей базы.
- Длина новых имён учитывает суффиксы превью и совпадений, ограничения UTF-8 и UTF-16. Старые файлы не переименовываются автоматически.
- При неудачном запуске macOS предусмотрена остановка только принадлежащего этому запуску дочернего сервиса. Поведение фонового запуска Linux сохранено.
- Упаковка берёт только отслеживаемые Git файлы проекта и исключает локальные инструкции, секретные файлы и ссылки. Лицензии зависимостей сохранены.

## Воспроизводимые измерения

Сравнение выполнено одинаковым исправленным измерительным сценарием в свежих процессах: 20 запусков, без одновременных тестов и сборки. Для загрузки — по три запуска каждого варианта с чередованием порядка. Для остальных общих сценариев — по одному, поэтому они не доказывают устойчивый выигрыш.

| Сценарий | До | После | Ограничение вывода |
|---|---:|---:|---|
| Подготовка отчёта, 1500 записей, медиана трёх повторов | 0,356 с | 0,137 с | Содержимое CSV и JSON одинаковое; локальное измерение |
| Вычисление ключа корня для этого отчёта | 1503 вызова | 1 вызов | Проверки перед сохранением отчётов остаются |
| Загрузка 250 файлов, медиана времени | 3,198 с | 3,295 с | Общего ускорения загрузки не подтверждено |
| Загрузка 250 файлов, медиана CPU | 3,734 с | 3,719 с | Диапазоны измерений пересекаются |
| Загрузка 250 файлов, средняя RAM | 70,558 МиБ | 70,266 МиБ | Малое различие, без обещания снижения RAM на реальных данных |

Во всех измерительных запусках выполнены проверки целостности. Количество сетевых запросов при обычной загрузке не изменилось: 254 запроса метаданных и 250 передач файлов. Сценарий обрыва действительно ожидал сеть больше пяти секунд: до восстановления не было готовых файлов, после восстановления все 250 файлов прошли SHA-проверку.

Логическое чтение в модели обхода выросло с 34,975 до 41,055 МиБ. Два необходимых чтения описи для проверки целостности объясняют 98,43% прироста. В сценарии дозагрузки чтение выросло с 16,448 до 18,148 МиБ; окончательная опись объясняет лишь 38,6% прироста, остальное не атрибутировано. Заявления о снижении всех ресурсов нет.

## Что проверено и что остаётся

Основной локальный прогон перед подготовкой публикации: **813 тестов прошли, 5 пропущены, ошибок нет**, 325,60 с. Проверены отмена и восстановление, настоящие блокировки SQLite, резервные копии, существующие файлы, Range, независимые SHA/MD5-проверки, профили, асинхронные команды интерфейса и защита локального HTTP API.

Настоящий пересобранный Windows EXE запускался с отдельными тестовыми папками состояния. Проверены запуск веб-интерфейса, мини-окно, трей, повторный запуск, закрытие, освобождение процессов и порта, повреждённые настройки, восстановление обычной и переносимой истории, диагностика ошибки SQLite и глубокий путь состояния. Проверка списка локальных папок через API не равна ручной проверке системного окна выбора папки.

Локально не проверялись настоящая замена работающего EXE обновлением, физическое отключение питания, реальный NAS и длительная загрузка из Яндекс.Диска. Полный браузерный E2E всех форм не выполнялся: часть сценариев интерфейса проверена через Node DOM-модель. Нативные проверки macOS и Linux выполняются отдельно в GitHub Actions; их результаты следует оценивать по конкретной ревизии.

Четыре исходные гипотезы остаются неподтверждёнными; отсутствие ошибок во всех возможных условиях не заявляется. Проверка точных состояний жёстких ссылок на NTFS не заменяет нативный тест аварийного завершения на POSIX.
