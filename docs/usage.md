# Подробная инструкция Disk Downloader

Приложение на Python для скачивания личного Яндекс.Диска через официальный REST API. Локальный интерфейс на русском языке, Flask и Waitress, очередь и состояние в SQLite. Сервер слушает только `127.0.0.1`. MIT.

## Запуск на Windows

Нужен Python 3.11 или новее с pip и tkinter. Проверено на Windows с Python 3.14.3. На другом ПК распакуйте проект и откройте **start.cmd** двойным щелчком. При первом запуске нужен интернет для установки зависимостей. Либо в PowerShell, находясь в папке проекта, выполните одну команду:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

`ExecutionPolicy Bypass` действует только на этот запуск PowerShell и не меняет системную политику. Скрипт создаёт `.venv` и устанавливает зависимости при первом запуске, а при изменении requirements.txt обновляет их. После установки приложение запускается также напрямую:

```powershell
.\.venv\Scripts\python.exe run.py
```

Откроется браузер: **http://127.0.0.1:8766**. Если автоматическое открытие не сработало, откройте этот адрес вручную. Завершение — `Ctrl+C` в терминале сервера. Для другого порта: `run.py --port 8767`. Для запуска без открытия браузера: `run.py --no-browser`. Путь состояния можно сменить параметром `--state-dir C:\DiskState`.

Во время подготовки проекта зависимости уже установлены. Если `.venv` существует, но установка была прервана, восстановите её командой `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`.

## Перенос и GitHub

Архив проекта содержит исходники, тесты, зависимости, MIT-лицензию и документацию. Локальные токены, результаты, `.state`, `.venv` и кэши в него не входят. Python и виртуальное окружение создаются на каждом ПК отдельно; копировать `.venv` между компьютерами не нужно.

Для GitHub распакуйте архив и загрузите содержимое папки `disk-downloader`, включая `.gitignore`. Проект ничего не публикует автоматически. На другом компьютере скачайте ZIP репозитория, распакуйте его, установите Python и запустите `start.cmd`. Токен каждый пользователь вводит у себя в браузере.

## Получение токена

1. Откройте [Яндекс OAuth](https://oauth.yandex.ru/client/new/) и зарегистрируйте приложение «Для доступа к API или отладки» для своего аккаунта.
2. В доступах выберите **`cloud_api:disk.read` — чтение всего Диска**. Приложению не нужны права записи или удаления, а также `cloud_api:disk.info`: соединение проверяется чтением корня.
3. Скопируйте `ClientID`. Откройте `https://oauth.yandex.ru/authorize?response_type=token&client_id=ВАШ_CLIENT_ID` в своём браузере, подтвердите доступ и получите токен на странице отладки. Для приложения доступа к API Яндекс использует `https://oauth.yandex.ru/verification_code` как redirect URI.
4. Вставьте токен в скрытое поле локального интерфейса и нажмите «Подключить». Не присылайте токен в чат, не помещайте его в командную строку, `.env` или исходники.

Официальные инструкции: [регистрация приложения доступа к API](https://yandex.ru/dev/id/doc/ru/register-api), [REST API Диска](https://yandex.com/dev/disk/rest/), [метаданные, пагинация и размеры превью](https://yandex.ru/dev/disk-api/doc/ru/reference/meta), [скачивание оригиналов](https://yandex.ru/dev/disk-api/doc/ru/reference/content). Максимальный предопределённый размер превью — `XXXL`, 1280 px по большей стороне; `preview_crop=false`.

## Работа с приложением

1. Подключите Диск. Переходите по папкам через имена, хлебные крошки, «Назад» и «Вверх». Таблица и сетка показывают по 100 элементов; сортировка применяется API ко всей папке, текстовый фильтр — к текущей странице. Выбор сохраняется между папками и страницами. Пагинация интерфейса не ограничивает очередь задания.
2. Отметьте файлы и папки или включите «Скачать весь Диск». Подпапки обходятся автоматически; вложенные и повторяющиеся выборы объединяются. Весь Диск означает `disk:/`, включая пустые каталоги и файлы любого типа.
3. Выберите папку назначения системным диалогом либо введите абсолютный путь. Внутри неё создаётся новая папка `Disk-<id>`. Приложение не использует существующие чужие файлы как подтверждённые результаты и не перезаписывает их.
4. Выберите режим и один или несколько отчётов: CSV, JSON, HTML, TXT. Размер превью, 1–8 потоков, 1–9 попыток и лимит одной попытки 5–180 секунд находятся в свёрнутых «Дополнительных настройках». По умолчанию — **только превью**, `XXXL`, 8 потоков, 1 попытка всего, 20 секунд на попытку.
5. Нажмите «Оценить выбранное». Пока идёт обход, показываются найденные файлы, папки и известный объём, без общего процента. После обхода проверьте оценку и нажмите «Начать». Потоки, попытки и время можно изменить перед запуском, продолжением остановленного задания или повтором неудачных файлов. Расширенные счётчики, оценка запаса места, параметры и локальные пути доступны в «Подробностях задания».
6. Пользуйтесь паузой, продолжением и остановкой. Пауза действует на границе запроса или блока данных. Уже выполняющийся сетевой запрос может закончиться либо дойти до таймаута. Остановка отменяет незавершённые файлы, сохраняя подтверждённые результаты.
7. После загрузки отчёты и ZIP создаются автоматически в фоне. ZIP сохраняется только в выбранную локальную папку. Кнопка «Открыть папку с ZIP» открывает её в Проводнике и не скачивает дополнительную копию в браузерные «Загрузки»; путь указан в подробностях задания.
8. «Повторить неудачные» повторяет ошибки файлов, отсутствие превью, неудачные обходы и замены оригиналов на превью. «Собрать ZIP результатов» позволяет упаковать частичные результаты после остановки; их статус остаётся «Остановлено».

Одновременно выполняется одно задание; внутри него загрузки параллельны. История интерфейса показывает последние 30 заданий; старые записи и результаты остаются на диске, это не ограничивает число файлов задания.

Папка состояния блокируется на время работы сервера. Два процесса не могут одновременно изменять одну очередь даже на разных портах; для отдельного экземпляра нужны другой порт и отдельная `--state-dir`. Cookie сессии имеет имя с портом, поэтому другие локальные Flask-приложения не мешают CSRF-защите.

## Режимы и результаты

| Режим | Поведение |
| --- | --- |
| Только превью | Скачиваются только превью API. Оригиналы для генерации превью не загружаются. Отсутствие превью отражается отдельно. |
| Оригиналы и превью | Обе загрузки выполняются независимо. Ошибка одной не мешает другой. Частичный результат отмечается `partial`. |
| Оригинал, превью при неудаче | Сначала оригинал и его проверка. После исчерпания попыток — превью. Успешный оригинал исключает загрузку превью. |

В режиме приоритета оригинала отчёты различают проверенный оригинал, замену на превью и отсутствие обоих результатов. Замены показываются в отдельном счётчике и в списке ошибок. 100% означает обработку очереди, включая ошибки и отмены, а не гарантированную полноту данных.

Пример структуры результата:

```text
Disk-a1b2c3d4e5f6/
  Фото/2024/отпуск.jpg
  Фото/2024/отпуск.jpg.preview.png
  Пустая/
  report-1.csv
  report-1.json
  result-1.zip
```

Суффикс превью сохраняет исходное расширение в имени; конечное расширение определяется по фактическому изображению. Оригинальный путь всегда сохраняется в состоянии и отчётах. Каталоги относительно корня Диска сохраняются при любом выборе. Недопустимые имена Windows, зарезервированные имена, длинные компоненты и совпадения без учёта регистра получают стабильный хеш-суффикс. Используются расширенные пути Windows. Подробности в [архитектуре](architecture.md).

Отчёты и ZIP сохраняются прямо в папке импорта `Disk-<id>`, без вложенной папки результатов. Пересборка создаёт `report-2.*`, `result-2.zip` и последующие версии. При совпадении с исходным или посторонним локальным файлом имя получает суффикс; существующий файл сохраняется. Внутри ZIP отчёты находятся в отдельной служебной папке `__disk_service_<id>/reports`, чтобы не смешиваться с содержимым Диска.

## Оценка места и ZIP

Размеры оригиналов берутся из метаданных. Размеры превью до скачивания неизвестны и показываются отдельно. В режиме приоритета оригинала оценка опирается на оригиналы; итог зависит от успешности загрузки. Отсутствующие размеры не считаются нулевыми.

ZIP использует `ZIP_STORED`: сжатие не выполняется, что экономит CPU и даёт понятную основу оценки. До загрузки показывается приблизительный объём известных данных, отдельно неизвестные размеры и служебные накладные расходы. Дополнительное место оценивается консервативно как два известных объёма сверх результата: архив плюс временные файлы. В заданиях с неизвестными размерами это не гарантированный достаточный запас. Новые версии, старые архивы и отчёты также занимают место.

После упаковки показываются фактические байты ZIP. Архив поддерживает ZIP64, сохраняет каталоги и содержит только подтверждённые результаты и выбранные отчёты. Исходники, временные файлы, OAuth-токен и временные ссылки в него не включаются.

## Восстановление

Состояние — `.state/jobs.sqlite3`. Временные `.part` создаются непосредственно в папке импорта на том же диске и удаляются после завершения попытки. После перезапуска токен отсутствует: введите его снова, выберите задание и нажмите «Продолжить». Обход продолжается с сохранённых смещений страниц. Незавершённый файл скачивается заново; побайтовое HTTP Range-восстановление не реализовано.

Подтверждённый результат повторно не скачивается, если актуальные метаданные источника, размер и локальный SHA-256 совпадают. При повторе актуальный оригинал исключает новую загрузку превью. Повреждённый или изменившийся результат получает новое имя; прежний файл сохраняется на диске и не включается в новый ZIP. Неудачные/устаревшие результаты не маскируются под актуальные.

API не предоставляет приложению атомарный снимок всего Диска. При изменениях содержимого папок во время пагинации возможны изменения списка между запросами. Для согласованной полной копии не меняйте Диск во время обхода; при существенных изменениях создайте новое задание. Продолжение существующего задания перепроверяет его файлы, но не обнаруживает автоматически все новые файлы в уже обойдённых папках.

## Безопасность

OAuth хранится только в памяти процесса и передаётся заголовком только официальному API и разрешённому серверу превью. Отключение отменяет задания, закрывает активные ответы и очищает токен. Токен не записывается в SQLite, отчёты, журналы или браузерные хранилища. Python не гарантирует физическое обнуление ранее выделенных строк в памяти; это не хранилище секретов от процессов с доступом к памяти.

Приложение проверяет Host, Origin, адрес клиента, `Sec-Fetch-Site` и CSRF-токен с сессией SameSite Strict. Нет CORS-доступа для сторонних сайтов. Ссылки получаются исключительно от API; разрешены только HTTPS-хосты Диска/хранилища Яндекса. Перенаправления проверяются вручную, токен не передаётся на хосты хранения оригиналов. TLS-проверка включена. При новом неизвестном CDN-хосте загрузка завершится понятной ошибкой, а не ослаблением проверки.

Файлы не могут выходить из папки задания; символьные ссылки и junction внутри неё запрещены. Завершение файла — проверка ответа, размера, доступных MD5/SHA-256, затем атомарное переименование без перезаписи на Windows. На других ОС используется hard link. HTTP 429/5xx и Retry-After учитываются, истёкшие ссылки запрашиваются заново.

Отчёты HTML экранируют данные и не используют внешних ресурсов; CSV — UTF-8 BOM, `;`, кавычки и защита от формул Excel. Приложение не выполняет пользовательский ввод через shell, не отправляет телеметрию и не изменяет Яндекс.Диск. Локальная ОС и другие процессы, имеющие доступ к папке/памяти пользователя, считаются доверенными; не запускайте сервер через внешний прокси и не открывайте его другим компьютерам.

## Дозагрузка недостающего

Выберите «Как загрузить → Дозагрузить недостающее» и укажите саму папку предыдущего импорта `Disk-…`. Новая вложенная папка не создаётся. Если сведения о предыдущем импорте найдены, исходные пути используются из него; другой выбор файлов/папок можно задать явно.

Диск обходится заново, поэтому в очередь попадают также новые файлы. При дозагрузке любой выбранный режим действует как приоритет оригинала: проверенный оригинал исключает новую загрузку превью, для имеющихся превью программа пробует получить оригиналы. Сначала обрабатываются источники без проверенной копии, затем источники только с превью и последними — источники с оригиналами. Существующие результаты проверяются по свежим метаданным, размеру и SHA-256. Загружаются недостающие, повреждённые или устаревшие результаты. Полный оригинал без прежнего состояния можно подтвердить хешем из API. Неподтверждённые превью заново проверяются загрузкой; один только факт наличия файла не подтверждает актуальность. Чужие и старые файлы не удаляются и не перезаписываются.

Для переноса папки на другой ПК приложение хранит небольшой `.disk-import*.sqlite3` прямо в корне импорта. Это локальное состояние, не дополнительный отчёт. В нём есть маппинг путей и хеши, без токена и временных ссылок; оно не включается в ZIP контента. При переносе всей локальной папки сохраняйте этот файл. Старые импорты распознаются также по общей SQLite-базе приложения; для папок без сведений о прежнем импорте нужно явно выбрать исходные пути или весь Диск.

## Попытки и время

«Попытки» — максимальное число попыток для оригинала или превью, **включая первую**: значение 3 означает максимум 3, а не 4. В режиме приоритета оригинала после этих попыток начинается отдельная ветка превью со своим таким же пределом. Запрос ссылки и передача файла входят в одну попытку; внутренних повторов внутри неё нет. Фактические числа попыток записываются в отчёты отдельно для оригинала и превью.

«Лимит попытки, с» ограничивает её полную активную длительность: ожидание перед повтором, получение ссылки, перенаправления и потоковую передачу. Медленная непрерывная передача также прекращается по этому лимиту: контрольный поток закрывает сетевое соединение. Пауза не расходует лимит. Это лимит одной попытки, а не всего задания или всех попыток файла; упаковка ZIP в него не входит.

Перед запуском, продолжением остановленного задания и повтором неудачных загрузок новые значения потоков/попыток/времени сохраняются в параметры задания. Для изменения ограничений у задания, находящегося на живой паузе, сначала остановите его и затем продолжите с новыми значениями. Уже проверенные файлы при этом пропускаются.

## Место на ПК

Основной счётчик «Результаты на ПК» включает актуальные оригиналы и превью задания, его отчёты, ZIP, переносимую опись и текущие временные файлы. Старые версии исходных файлов и постороннее содержимое не входят в этот счётчик. Это сумма размеров файлов, а не размер выделенных блоков файловой системы. Свободное место показывает ОС для выбранного диска. «Передано» отдельно учитывает сетевые байты, в том числе неудачные попытки; оно может превышать сохранённый объём.

## Типы файлов и оставшееся время

Группы для скачивания: фото, видео, музыка, другие файлы (документы, архивы и прочее). Сначала используется media_type Яндекса, затем MIME, затем известные расширения, включая RAW/HEIC и распространённые форматы видео/аудио. Все папки и страницы обходятся независимо от фильтра; в очередь попадают только выбранные типы. Фильтр сохраняется в настройках и переносимой описи; дозагрузка без нового явного списка типов использует прежний фильтр. Исключённые копии остаются на ПК, но не включаются в новый ZIP.

Превью скачиваются только для фото и видео, если их предоставляет API. Выбранная музыка и другие файлы скачиваются оригиналами при любом режиме. Если тип источника изменился после обхода, неподходящий файл отмечается как исключённый и не скачивается.

Оставшееся время рассчитывается по последним примерно 30 секундам активной работы, после минимум двух секунд наблюдения. При неизвестных размерах используется скорость обработки источников. Для текущего файла учитываются Content-Length и уже принятые байты. Пауза не входит в активное время; остановка и новый запуск сбрасывают выборку. Отдельно оценивается упаковка ZIP. Оценка приблизительная, не включает будущую упаковку в показание загрузки и может меняться при повторах, проверке кеша и неравномерных размерах файлов.
