# Инструкция YaDiskDownloader

## Запуск

**Windows 10/11 x64:** полностью распакуйте Windows ZIP из раздела Releases и откройте `YaDiskDownloader.exe`. Python устанавливать не нужно. Интерфейс откроется в браузере по адресу `http://127.0.0.1:8766`.

**Исходники:** установите Python 3.11+ с pip и tkinter, распакуйте исходники и откройте `start.cmd`. При первом запуске нужен интернет для установки зависимостей.

**Windows-CMD.zip:** отдельный вариант запуска через `start.cmd`. Установите Python 3.11+ с pip и tkinter, полностью распакуйте архив и откройте `start.cmd`. Окно CMD должно оставаться открытым. Инструкция находится в `START-CMD.txt` внутри архива.

После закрытия браузера загрузка продолжается. Значок в трее позволяет открыть интерфейс, поставить задание на паузу, продолжить и завершить приложение. Для выхода также доступна кнопка в разделе «Обновления и диагностика».

## Подключение Яндекс.Диска

1. Войдите в нужный аккаунт и откройте [создание приложения Яндекс OAuth](https://oauth.yandex.ru/client/new/).
2. Выберите приложение «Для доступа к API или отладки», укажите название и контактную почту. Добавьте только **`cloud_api:disk.read` — чтение всего Диска**.
3. Создайте приложение и скопируйте ClientID. В интерфейсе Downloader нажмите **«Как начать»**, на втором шаге вставьте ClientID и откройте получение токена.
4. Подтвердите доступ на сайте Яндекса и вставьте полученный токен в поле OAuth-токен в Downloader. Нажмите «Подключить».

Токен хранится только в памяти. После перезапуска его нужно ввести заново. Приложение читает Диск; права записи и удаления не нужны. Официальная справка: [регистрация приложения](https://yandex.ru/dev/id/doc/ru/register-api), [получение токена](https://yandex.ru/dev/id/doc/ru/tokens/debug-token).

## Выбор и оценка

Отметьте файлы и папки либо включите «Скачать весь Диск». Выбор сохраняется при переходах между страницами списка. Выберите папку на ПК и нужные типы: фото, видео, музыка, другие файлы. Превью скачиваются только для фото и видео; музыка и другие файлы скачиваются в оригинале.

| Режим | Результат |
| --- | --- |
| Только превью | Превью фото и видео; оригиналы остальных выбранных типов. |
| Оригиналы и превью | Оба варианта, если они доступны. |
| Оригинал, превью при неудаче | Оригинал; при неудаче — превью, если оно доступно. |

Нажмите «Оценить выбранное». После обхода выполняется подготовка локальных путей и сравнение с предыдущим импортом. Этап подготовки и число обработанных объектов видны в задании. После готовности нажмите «Начать».

При дозагрузке до начала скачивания программа проверяет локальные файлы. Проверенные оригиналы сразу попадают в прогресс. Счётчик «Уже есть результат» включает и проверенные превью; файлы только с превью остаются в очереди на получение оригинала. Ход проверки папки показан отдельно в файлах, а занимаемое место подписано «На устройстве».

«Объём по папкам» показывает количество файлов и суммарный размер исходных оригиналов. Нажмите папку для детализации. Неизвестные размеры учитываются отдельно. Размеры превью заранее неизвестны; оценка ZIP предварительная.

Общие папки других пользователей и фото из безлимита могут попадать в выбор, не расходуя вашу облачную квоту. Поэтому объём скачивания может превышать занятое место, указанное Яндексом.

## Исключения

В «Исключениях папок и файлов» укажите по одному правилу на строку:

```text
disk:/Фото/Черновики
disk:/Документы/private.pdf
*.tmp
Фото/Экспорт/*
```

Точный путь исключает файл или всю папку. Шаблоны имён действуют на любой глубине; шаблоны с `/` сравниваются с путём относительно корня Диска. Шаблоны не учитывают регистр, точные пути `disk:/…` учитывают. Кнопка ⊖ в списке добавляет объект в исключения. Изменённые правила применяются при следующем обходе.

## Настройки загрузки

По умолчанию: **8 потоков, 1 попытка, 20 секунд на попытку**. Число попыток включает первую. Оригинал и превью имеют отдельный предел. Умные потоки временно отключены: используется выбранное число потоков.

«Общая скорость, МиБ/с» ограничивает суммарную передачу файлов всех потоков. 0 — без ограничения. Ожидание этого ограничения и ручные паузы не расходуют сетевой бюджет попытки. Миниатюры в браузере, обход списка и проверка обновлений не входят в лимит передачи файлов.

Для изменения потоков, попыток, времени или скорости живого задания остановите его и продолжите с новыми настройками. «Пауза» сохраняет текущую работу; «Остановить» завершает операцию с сохранением результатов и пригодных недокачанных частей.

Автопауза учитывает заполнение диска назначения. Порог задаётся пользователем, по умолчанию — 95%. Освободите место и нажмите «Продолжить»; порог можно изменить во время паузы. Дополнительный небольшой запас защищает от полного заполнения диска.

Профили сохраняют выбор, папку назначения и параметры загрузки. Для использования выберите профиль и нажмите «Применить». Токен в профиль не входит.

## Результаты и ошибки

Для новой загрузки создаётся папка `Disk-…`. Файлы, отчёты, ZIP и HTML-журнал сохраняются прямо в ней. Исходные папки сохраняют структуру; несовместимые с Windows имена преобразуются. Превью имеют суффикс `.preview` и не заменяют оригинал. Существующие чужие, изменённые и повреждённые файлы не перезаписываются: для нового результата создаётся отдельное имя.

ZIP создаётся, если включено «Создать ZIP после загрузки». Позже доступна кнопка «Собрать ZIP». Кнопка открытия папки не скачивает вторую копию ZIP в браузерные «Загрузки». Папка служебных отчётов внутри ZIP отделена от исходных данных.

Если оригинал или превью успешно сохранён, неудача другого варианта не попадает в ошибки. Подробности остаются в соответствующей группе журнала. Ошибками считаются файлы без результата и прочие ошибки, включая ошибки файловой системы и обработки. Для неудачных файлов доступны повтор всех, одного или выбранных записей. Для успешно сохранённого превью можно снова попробовать получить оригинал через дозагрузку или «Повторить недостающий вариант».

100% означает обработку очереди; при ошибках это не гарантирует полноту результата.

## Дозагрузка существующей папки

Выберите «Как загрузить → Дозагрузить недостающее» и укажите **саму прежнюю папку `Disk-…`**. Нажмите «Оценить выбранное», затем «Начать».

Программа заново обходит источники. Подтверждённые прежние оригиналы сразу учитываются в прогрессе и исключаются из оставшегося объёма. Для них превью не скачивается. Сначала обрабатываются файлы без результата, затем файлы только с превью: для них программа пытается получить оригинал. Если оригинал недоступен, проверенное превью остаётся результатом.

Счётчик «Ранее сохранено» показывает прежние результаты. Сохранённая проверка повторно используется при совпадении метаданных источника и сигнатуры локального файла. На Windows учитывается также ChangeTime. Изменённые файлы, копии на другом ПК и файлы без пригодной сохранённой проверки снова проверяются по контрольной сумме. Новые скачанные данные проверяются всегда.

Импорт соответствует метаданным нового обхода. Если Диск изменился после оценки, выполните новый обход для сравнения с обновлённым содержимым. Повторное продолжение завершённого задания также обновляет метаданные обрабатываемых файлов.

При переносе результатов копируйте всю папку, включая `.disk-import*.sqlite3` и части `.disk-….part`. Для распознанных оригиналов без переносимой описи программа может подтвердить обычное совпадающее имя по облачной контрольной сумме. Превью без описи не принимаются за подтверждённые результаты по одному только имени.

## Место на ПК и оставшееся время

«Объём папки на ПК» учитывает всё содержимое выбранного импорта: прежние файлы, отчёты, ZIP и части. Пересчёт идёт в фоне примерно каждые 10 секунд. Ссылки на внешние папки не обходятся. Это сумма размеров файлов, а не размер выделенных блоков файловой системы. Свободное место показывает ОС для диска назначения.

Скорость и «Передано» относятся к сетевым данным текущей операции, включая неудачные попытки. Оставшееся время уточняется по ходу загрузки; неизвестные размеры превью могут сделать его неточным. Пауза отображается отдельно.

## Изменения и журнал

«Изменения» сравнивает обход с прежним импортом: новые, изменённые, прежние, исчезнувшие, исключённые и непроверенные источники. Первый импорт создаёт исходный список. Перенос или переименование отображается как исчезновение старого пути и появление нового. Ошибка чтения папки не считается удалением; локальные копии не удаляются.

После загрузки сохраняется отдельный `changes.html`; он включается в ZIP со служебными отчётами. Для старых переносимых импортов без списка источников сначала нужен один новый обход.

Отдельный `log.html` сохраняется каждые 5 минут во время работы, включая паузу, и при завершении. Он содержит группы, поиск и страницы, открывается без сервера и не включается в ZIP результатов. Токены и временные ссылки скрываются; имена файлов и локальные пути остаются в журнале.

## Если пропала связь

При сетевом обрыве в карточке задания появляется предупреждение: «Нет связи с Яндекс.Диском. Проверьте интернет». Обход и загрузка ждут восстановления доступа. Программа проверяет доступность API Диска без токена; ответ HTTP, включая 401 или 405, подтверждает наличие связи. После неуспешной проверки повтор выполняется примерно через секунду, сама проверка ограничена тремя секундами.

Когда связь возвращается, зависшие соединения закрываются и запросы выполняются заново без прежнего ожидания повторов. Время ожидания связи не расходует попытки загрузки. Проверенные части продолжаются через Range, если сервер это поддерживает; иначе файл скачивается заново. Проверка контрольной суммы остаётся обязательной.

Ручная пауза не снимается автоматически. Задание можно остановить и без интернета. Потеря связи и восстановление отмечаются в журнале. HTTP 403/404/429/5xx не означают исчезновение интернета и сохраняют обычные правила обработки ошибок и повторов. Если недоступен только сервер конкретного файла, а API Диска отвечает, применяется обычное ограничение попыток.

## Обновление и история

История и профили исходников и EXE находятся в `%LOCALAPPDATA%\YaDiskDownloader`. После закрытия старого экземпляра обновите EXE или исходники и запустите программу заново. Токен вводится снова.

При первом переходе со старой `.state` обновите файлы в прежней папке либо распакуйте новую установку рядом. Программа ищет прежнее состояние возле своей папки и в соседних папках Disk Downloader / YaDiskDownloader. Она переносит задачи, профили, имена результатов, контрольные суммы и информацию о частях; сами результаты и старая база остаются на месте. Новая история не заменяется старыми записями с тем же ID. Профили с одинаковыми именами сохраняют настройки новой установки.

База работающего старого экземпляра не переносится; после его закрытия поиск повторится при следующем запуске. Задачи, прерванные обновлением, доступны после подключения Диска через «Продолжить». Дальнейшие обновления используют общую историю независимо от места распаковки.

Явный `--state-dir` задаёт отдельное состояние и отключает автоматический поиск старой установки для этого запуска. Для второго экземпляра нужны отдельная папка состояния и другой `--port`.

## Диагностика и сообщение об ошибке

Нажмите кнопку версии сверху. Проверка обновлений открывает ссылку на новый релиз, если он доступен; её можно отключить. Установка выполняется только по кнопке «Установить и перезапустить», после скачивания и проверки архива. Во время активной работы установка недоступна.

В диагностике выберите задание, посмотрите состав и сохраните ZIP. Он содержит параметры, среду, счётчики, классификацию ошибок и до 2000 событий; без токена, имён и путей файлов, исходного содержимого и базы данных.

«Сообщить об ошибке» готовит заголовок и описание с версией, ОС и счётчиками задания. Проверьте свой текст, затем откройте форму GitHub и подтвердите отправку на сайте. ZIP диагностики можно приложить вручную. Личные данные в написанном пользователем описании нужно убрать перед отправкой.

## Безопасность переносимых частей

Для частей, перенесённых из другой установки или импорта, программа создаёт новую служебную копию проверенного префикса. Прежняя часть сохраняется; обе копии учитываются в объёме папки. Запись через жёсткие ссылки запрещена.

При запуске через start.cmd pip обновляется до версии из requirements-bootstrap.txt отдельным шагом перед установкой зависимостей. Для ручной установки сначала выполните `python -m pip install --upgrade -r requirements-bootstrap.txt`, затем установите requirements.txt.


## Функции версии 1.3.0

История, очередь, локальная проверка, резервные копии, очистка и обновление EXE описаны в [инструкции 1.3.0](features-v1.3.0.md). В текущей версии отчёты и журнал имеют постоянные имена и обновляются в той же папке; старые нумерованные копии сохраняются. Допускается от 1 до 8 потоков, по умолчанию 8.

## Оценка времени

Для оригиналов оценка строится по устойчивой передаче данных с известным оставшимся объёмом. Для превью и перехода к ним после ошибок учитывается фактическое время полных циклов обработки файлов, включая попытки и повторы. Параллельность учитывается по числу реально завершённых файлов за прошедшее время.

Одиночный пакет данных не используется для прогноза всей очереди. При серии неудач, отсутствии передачи или недостатке наблюдений показывается причина уточнения. Быстрое обнаружение ранее скачанного не увеличивает расчётную скорость загрузки. После перехода к получению оригиналов для файлов с превью статистика собирается заново. Паузы и ожидание сети исключены, а время ZIP оценивается отдельно.

## Остановка и выход

Панель текущего задания над вкладками позволяет перейти к нему или остановить его, даже если открыта другая запись истории. Кнопки паузы, остановки и продолжения находятся сразу под прогрессом. При обходе показано число найденных файлов; общий процент появится после завершения списка.

«Остановить обход» сохраняет найденные записи. «Продолжить обход» возвращает к оценке без автоматического скачивания. Чтобы скачать файлы после оценки, нажмите «Начать скачивание».

Закрытие вкладки браузера оставляет приложение работающим. Для завершения используйте «Выход» сверху или в меню трея. Программа отменяет запросы и сохраняет прогресс. Если фоновый поток не отвечает, текущий процесс принудительно завершается не позднее 15 секунд после команды выхода; при следующем запуске проверяются сохранённые результаты и части. Старые задания и профили с количеством потоков больше 8 автоматически ограничиваются восемью.
