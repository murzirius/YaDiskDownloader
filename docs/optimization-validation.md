# Проверка оптимизации трафика и ресурсов

Платформа: Windows, Python 3.14.8, SQLite 3.51.3. Использовались искусственные файлы и локальный HTTP-сервер. Настоящий Яндекс.Диск и скорость зарубежных серверов этими замерами не проверялись.

## Подтверждённые изменения

| Проверка | До | После |
|---|---:|---:|
| Запросы метаданных для 300 оригиналов в режиме экономии | 304 | 4 |
| Транзакции SQLite при загрузке 300 файлов | около 5140 | около 4540 |
| TCP-соединения для 20 последовательных JSON-запросов | 20 | 1 |
| Полезная нагрузка ответов для этих запросов | 1 103 380 байт | 19 480 байт |
| Неизменённое состояние задания в интерфейсе | 3916 байт | 70 байт |
| Загрузки одной миниатюры при трёх открытиях | 3 | 1 |

Сокращение до четырёх относится только к запросам метаданных. Запросы ссылок скачивания и загрузки самих файлов остаются. Кэш сведений ограничен размером и временем; на долгом обходе экономия может быть меньше.

Размер ответов JSON измерен на контролируемом сервере с искусственными неиспользуемыми полями. Сочетание fields и gzip уменьшило эту нагрузку на 98,2%; это не обещание такого же сокращения всего трафика Яндекса. Фото, видео и другие оригиналы не сжимаются приложением.

## Сравнение ресурсов

Три чередующихся повтора старого и нового кода на одном ПК. В таблице медианы. Обход — 5000 файлов, остальные файловые сценарии — 300 файлов по 64 КБ. HTTP-отзывчивость измерялась через Flask test client, без браузерного и сетевого транспорта. В сценариях загрузки, обрыва, дозагрузки и ZIP проверены SHA-256 результатов и целостность SQLite; у ZIP проверено содержимое.

| Сценарий | Время до / после, с | CPU до / после, с | Пик RAM до / после, МБ |
|---|---:|---:|---:|
| idle | 6.00 / 6.01 | 0.00 / 0.00 | 67.53 / 68.09 |
| scan | 1.22 / 1.25 | 1.09 / 1.06 | 77.80 / 78.02 |
| download | 4.97 / 4.69 | 5.88 / 6.06 | 73.06 / 72.90 |
| pause | 6.01 / 6.01 | 0.09 / 0.12 | 72.07 / 72.05 |
| offline | 11.98 / 11.61 | 5.31 / 6.55 | 74.02 / 74.03 |
| missing | 1.08 / 1.18 | 1.25 / 1.33 | 71.55 / 71.78 |
| zip | 0.87 / 0.85 | 0.98 / 0.95 | 72.00 / 72.21 |

Время на общих CI-серверах зависит от нагрузки. Предупреждение о скорости требует повторного замера; проверки целостности и предел памяти обязательны.

Простой и пауза длятся фиксированные шесть секунд; это не время выполнения задания. Нулевое значение CPU означает предел разрешения короткого замера, а не отсутствие фоновых процессов. Пиковая RAM в этих сценариях практически не изменилась.

Общее ускорение обхода и снижение CPU этими повторами **не подтверждены**. У загрузки медиана времени снизилась примерно на 6%, но диапазоны повторов перекрываются. В сценарии обрыва медиана CPU выросла с 5,31 до 6,55 с при широком разбросе: 4,86–6,63 с до и 4,78–7,67 с после. Это остаётся предметом наблюдения, а не основанием обещать ускорение. Измеримые результаты — меньше запросов, переданных метаданных и вспомогательных транзакций.

## Проверки корректности

- Общий прогон в изолированной копии: 854 успешных проверки, 6 пропусков по условиям платформы. Дополнения после этого прогона проверяются отдельно.
- Проверены TTL, предел памяти и смена ключа у кэша; восстановление полного состояния при пропуске ревизии.
- На реальном локальном сокете проверены gzip, повторное использование соединения, смена ключа и таймаут тёплого соединения с последующим успешным запросом.
- Проверены остановка после текущих файлов, продолжение, ранний старт и повтор только выбранной группы ошибок.
- Синтетический набор для облачной проверки проверен по собственным SHA-256. Отсутствие токена завершает проверку с ошибкой настройки, без запросов в облако.

Внешняя служба синхронизации может создавать жёсткие ссылки на рабочие исходники. Упаковщик продолжает запрещать такие файлы. Проверки упаковки выполняются в отдельной копии обычных файлов; это ограничение защиты не ослаблялось.

## Непроверенное

Настоящий Яндекс.Диск, реальные ограничения скорости Яндекса и работа на Linux/macOS в этом локальном прогоне не проверялись. Новые workflow подготовлены; их выполнение GitHub Actions нужно проверить после отправки кода. У облачной проверки предусмотрены отдельный тестовый аккаунт, секрет среды, ограниченный набор файлов и отчёт без содержимого файлов и токена.


## Интерфейс и готовый Windows EXE

На 576 сочетаниях экранов и размеров текста проверены основные страницы, инструменты, новые панели трафика и установки, поиск настройки и переход к ней. После исправления интервалов кнопок: 0 геометрических ошибок, 0 ошибок JavaScript.

Настоящий EXE запускался отдельно от исходников. Проверены выбор папки, завершение через веб-интерфейс, значок в трее и мини-окно; порт и дочерние процессы освобождены. Проверены понятная диагностика искусственной ошибки SQLite и повтор после её исправления. В двух сценариях восстановления истории сохранены 1000 искусственных файлов, их SHA-256 и прежняя история.

После общего прогона проверены последние изменения отдельно: 116 успешных проверок и один платформенный пропуск; затем 52 проверки новых функций и упаковки. Дополнительно проверен настоящий локальный HTTPS: недоверенный сертификат отвергнут, доверенный тестовый сертификат принят, три запроса использовали одно TLS-соединение. Эти проверки не заменяют скачивание с настоящего аккаунта Яндекса.

Установка проверена на временных файлах: отказ от замены постороннего файла, откат при сбое и создание настоящего ярлыка Windows в изолированном меню. Полная установка через кнопку готового EXE в обычный профиль пользователя в этом прогоне не выполнялась.
